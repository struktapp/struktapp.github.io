Strukt

The application skeleton for the strukt4 package set. It ships almost
nothing of its own: a composer.json that pulls in
strukt/framework and a post-create-project-cmd hook that
scaffolds a runnable application through the framework console. Everything
under app/, cfg/, templates/, lib/, plus index.php and .env, is
generated and git-ignored.

Getting started

composer create-project strukt/strukt --prefer-dist

The install hook prompts for an application name, then runs two commands for
you:

vendor/bin/strukt app:make              # prompts for the name; scaffolds app/src/<Name>/..., cfg/*.ini and templates/
vendor/bin/strukt app:reload            # lib/App/Loader.php, index.php, .env

The result is a ready-to-run project:

.
├── app/
│   └── src/
│       └── {{app}}/
│           ├── User.php
│           └── AuthModule/
│               ├── {{app}}AuthModule.php     # the module (alias "au")
│               ├── Controller/User.php       # scaffolded, see "Controller facet"
│               ├── Form/User.php
│               ├── Router/Index.php
│               └── Tests/UserTest.php
├── cfg/                                      # generated application config
│   └── app.ini
├── templates/                                # editable scaffolding templates
├── lib/
│   └── App/
│       └── Loader.php                        # generated, do not edit
├── index.php                                 # generated front controller
├── .env                                      # generated environment
├── composer.json
└── vendor/

Run it

vendor/bin/strukt app:exec
# Serving on http://127.0.0.1:8080

Visit http://127.0.0.1:8080/ and http://127.0.0.1:8080/hello/ada — the
generated AuthModule ships with a welcome and a hello route.

Controller facet

Controller/User.php is scaffolded as a stub and is not routed by the generated
app — routes only come from Router/ classes. It exists to illustrate the
controller facet, whose actions other facets reach through the module alias:

// inside a router
return $this->get('au.ctr.User')->find($id);

The registrar indexes it as nr.au.ctr.User, and core('au.ctr.User') (or
Core::get()) resolves it through the facet provider. Real action classes can
either live here and be called this way, or sit directly in a router — the RBAC
routes in this skeleton take the latter approach for brevity.

Working in the monorepo

The skeleton resolves strukt/framework and its siblings through Composer
path repositories (../framework, ../base, …), so it installs against the
working copies next to it:

composer install
vendor/bin/strukt app:make {{app}}
vendor/bin/strukt app:reload

bin/clear resets the project back to its seed state by deleting every
generated artifact.

Sessions

The generated lib/App/Provider/Session.php binds the router's native
$_SESSION store — all a single-server app needs:

use Strukt\Contract\Http\SessionInterface;
use Strukt\Http\Session\Native;

router()->session(static fn (): SessionInterface => new Native());
router()->middleware('sess');

To share sessions across processes or servers, swap in the router's
cache-backed store, which writes through to a strukt/cache driver so any
worker can resume the session:

use Strukt\Http\Session\Cache;

router()->session(static fn (): SessionInterface => new Cache(memc('sess')));

memc() is the cache package's memcached helper. Give each client its own
namespace (memc('sess_' . $sid)) to keep sessions isolated. See the router's
HTTP layer and
authentication docs for the full set of
stores.

Strukt Framework

Annotation-driven application kernel, facades, and console for the strukt4
bundle set. This is the package that unifies the Strukt components under one
application lifecycle.

Most applications use it through the strukt/strukt skeleton.

Install

composer require strukt/framework

Requires PHP 8.2+ and a strukt4 powered project using base, commons, contract,
router, cache, event, form, rules, fs, generator, and console.

Quick start

use Strukt\Framework\Application;

$app = Application::make();
$app->register(new AuthModule());
$app->run();

handle() returns a ResponseInterface; run() sends it.

Application scaffolding

The framework publishes vendor/bin/strukt and a development-only
vendor/bin/xhttp binary.

vendor/bin/strukt list
vendor/bin/strukt help module:make
vendor/bin/strukt cache:clear

vendor/bin/strukt app:make payroll
vendor/bin/strukt app:reload
vendor/bin/strukt app:exec
# http://127.0.0.1:8080

app:make scaffolds app/src/<Name> and the configuration. app:reload
generates lib/App/Loader.php, index.php, and .env without overwriting
existing files. app:exec runs the PHP built-in server with index.php as the
router script.

Application namespaces resolve through Strukt\Framework\Autoload, so no
Composer autoload edits or composer dump-autoload are required.

Modules

A module groups application facets beneath one namespace.

use Strukt\Framework\Contract\Module;

final class AuthModule extends Module
{
    protected string $alias = 'auth';
}

Facets are indexed in the nr registry as nr.<alias>.<facet>.<name> and can
be resolved through core():

core('auth.ctr.Login', ['request' => request()]);

Routers and annotations

Routers carry method annotations that Application turns into routes on the
Strukt router.

use Strukt\Framework\Contract\Router;

final class Login extends Router
{
    /**
     * @Route(/auth/login)
     * @Method(POST)
     * @Form(Authentication)
     * @Middleware(sess)
     */
    public function login(\Strukt\Http\Request $request)
    {
        //
    }
}

Forms validate through strukt/form and strukt/rules; a failed form
submission produces a 422 response with field errors.

Dependency injection

The framework ships a small PSR-11 container, backed by strukt/base.

use Strukt\Container\Container;
use Strukt\Framework\Contract\Kernel;

$kernel = container()->get(Kernel::class);
$auth = container()->make(\App\Auth\Login::class);

container()->set(
    \App\Mailer::class,
    fn (Container $c) => new \App\Mailer($c->get(\App\Transport::class)),
);

Strukt Router

A typed HTTP router with parameter matching, a middleware pipeline, reflection
resolved actions, and form validation.

Routes are declared against patterns such as /user/{id:int}, matched by a
compiled regex with typed parameter extraction, guarded by middleware, and
dispatched by injecting the request, response, services, or a validated form.

Install

composer require strukt/router

Requires PHP 8.2+ and the strukt4 contract, form, cache, and event packages as
needed.

Quick start

use Strukt\Router\Router;
use Strukt\Contract\Http\RequestInterface;

$router = new Router();

$router->get('/', fn () => 'home');
$router->get('/user/{id:int}', fn (int $id) => "user[{$id}]");

$router->post('/login', fn (
    RequestInterface $request,
    Strukt\Contract\FormInterface $form,
) => $form->value('email'))->form(LoginForm::class);

$response = $router->kernel()->handle($request);
$response->send();

An application normally uses the shared instance instead:

router()->get('/', fn () => 'home');

Routing

Use one verb method per route, or any() for every common method.

$router->get('/list', fn () => 'list');
$router->post('/save', fn () => 'saved');
$router->put('/item/{id:int}', fn (int $id) => "put {$id}");
$router->patch('/item/{id:int}', fn (int $id) => "patch {$id}");
$router->delete('/item/{id:int}', fn (int $id) => 'deleted');
$router->options('/item', fn () => 'options');
$router->head('/item', fn () => 'head');
$router->any('/hook', fn () => 'any method');

Groups

$router->group('/api/v1', function (Router $router): void {
    $router->get('/users', fn () => 'users');
    $router->get('/users/{id:int}', fn (int $id) => "user[{$id}]");
});

Named routes

$router->get('/user/{id:int}', fn (int $id) => "user[{$id}]")
    ->name('user.show');

$router->path('user.show', ['id' => 7]); // /user/7

Route options mutate the registered route fluently: name(), middleware(),
permissions(), requiresAuth(), form(), and defaults().

Parameters

Pattern Matches Type
{name} any segment string
{id:int} digits int
{price:float} decimal float
{on:bool} true / false bool
{word:alpha} letters string
{key:alphanum} letters, digits, _, - string
{slug} slug words string
{on:date} YYYY-MM-DD string
{id:uuid} UUID string
{rest:*} remaining segments string 
$router->get('/user/{id:int}', fn (int $id) => "user[{$id}]");
$router->get('/blog/{year:int}/{?month:int}', fn (int $year, ?int $month = null) => '');
$router->get('/files/{rest:*}', fn (string $rest) => $rest);

Matched values are cast. An unknown type or missing required placeholder throws.
Reverse generation through uri() or Router::path() respects the same rules
and route defaults.

Middleware

Global middleware runs before every route; route middleware runs after that.
Definitions may be a registered name, class, object, or callable.

$router->middleware(TraceMiddleware::class);
$router->get('/admin', fn () => 'admin')->middleware('auth', 'authz');

Built-in names:

Name Class Purpose
sess Middleware\Session Attach the session store to the request.
auth Middleware\Authentication Resolve and bind the current user.
authz Middleware\Authorization Enforce required permissions.

Middleware resolves through constructor injection. A middleware class declares
the services it needs, and the router supplies them from the per-request service
map.

Authentication and permissions

use Strukt\Contract\Http\SessionInterface;
use Strukt\Contract\UserInterface;

$router->session(fn (): SessionInterface => new Strukt\Http\Session\Native());

$router->verify(fn (SessionInterface $session): ?UserInterface =>
    $session->get('email')
        ? new Strukt\User(email: $session->get('email'))
        : null
);

$router->permissions(fn (?UserInterface $user): array =>
    $user?->getEmail() === 'admin@example.com' ? ['admin'] : []
);

$router->get('/dashboard', fn (RequestInterface $request) =>
    $request->user()?->getEmail() ?? 'guest'
)->requiresAuth();

$router->get('/admin', fn () => 'admin')
    ->requiresAuth()
    ->permissions(['admin']);

A missing user on an authenticated route stops with 401. A user without the
required permission receives 403.

Forms

Attach a strukt/form class with form(). The router submits the request values
and validates before the action runs. A failing validation answers with 422 and
the errors as JSON.

$router->post('/login', fn (
    Strukt\Contract\FormInterface $form,
) => 'hi '.$form->value('email'))->form(LoginForm::class);

Responses

An action may return a string (body), an array (JSON), a ResponseInterface, or
null.

$router->get('/home', fn () => response()->redirect('/home'));
$router->get('/data', fn () => response()->json(['ok' => true]));
$router->get('/file', fn () => download('/tmp/report.pdf', 'report.pdf'));

The kernel maps exceptions to HTTP errors: 404 for an unknown path, 405 with an
Allow header for a bad method, 422 for failed form validation, and 401/403 for
the auth gates.

Helpers

Helper Purpose
router() The shared Router instance.
request($input, $method, $uri, $headers) Build a Request.
response($code, $headers) A fluent response builder.
route($path, $method, $input) Dispatch and return the response.
matcher($patterns) A standalone UrlMatcher.
redirect($url, $status = 302) A redirect response.
download($path, $filename) A file download.

HTTP layer

The package ships its own Strukt\Http stack implementing the strukt/contract
interfaces: Request with createFromGlobals(), Response, ResponseBuilder,
Download, and UploadedFile.

Session stores live under Strukt\Http\Session:

$router->session(fn (): SessionInterface => new Strukt\Http\Session\Native());
$router->session(fn (): SessionInterface => new Strukt\Http\Session\Cache(memc('sess')));

Native persists in $_SESSION. Cache persists through a strukt/cache
driver, so several processes or servers can share a session.

Module prefixes

In a Strukt application, module route prefixes are resolved in this order:

  1. Module class property or method: public string $prefix = '/api/v1' or
    public function prefix(): string.
  2. Router folder Prefix.php class: prefix() method, $prefix property, or
    getPrefix().
  3. Class-level annotation: @Prefix('/api/v1').
use Strukt\Framework\Contract\Module;

class PayrollAuthModule implements Module
{
    public string $prefix = '/api/v1';
}

Prefix joining follows Router::group() semantics, with the trailing slash
preserved for the root.

Strukt Commons

Chainable arrays and strings, dot-separated collections, date ranges, token
queries, registries, message stacks, JSON helpers, and common global functions.

Requires PHP 8.2+ and strukt/base. Optional integrations such as Ramsey UUID
and Symfony's English inflector are used when installed; standalone fallbacks
remain available.

Install

composer require strukt/commons

Composer loads the Strukt\ namespace and the global helpers. Require the
normal autoloader before using the helpers.

Collections and dot paths

collect() creates a mutable collection with dot-path reads and writes.

$contact = collect([]);
$contact->set('mobile', '+2540770123456');
$contact->set('work-phone', '+2540202345678');

$user = collect([]);
$user->set('contacts', $contact->yield());

echo $user->get('contacts.mobile');
$user->exists('contacts.mobile'); // true

$user->remove('contacts.work-phone');
$user->keys('contacts');          // ['mobile']

The dot(), attach(), and detach() helpers work directly on arrays.

$data = [
    'user' => [
        'firstname' => 'Gene',
        'db' => [
            'config' => ['username' => 'root'],
        ],
    ],
];

echo dot('user.db.config.username', $data); // root

attach('user.db.config.host', $data, 'localhost');
detach('user.db.config.username', $data);

Value objects

Value objects expose their raw value through yield(). Transformations return a
new wrapper so chains do not mutate the original.

DateTime

$start = when();
$end = when('+30 days');
$random = $start->rand($end);

$end->gt($start);   // true
$start->btwn($start, $end);

$start->gte($end);
$start->lte($end);
$start->equals($end);
$start->same(new DateTime());

$start->clone('+1 day');
$start->reset(); // 00:00:00
$start->last();  // 23:59:59

echo $start;

same() compares calendar dates; equals() compares the complete instant.

Today and date periods

period() controls an inclusive date range and can simulate the current day.

$period = period();
$period->create(when('1900-01-01'), when('1963-12-31'));
$period->reset(when('1960-03-23'));

$fakeToday = today();
echo $fakeToday->format('Y-m-d'); // 1960-03-23

$fakeToday->hasPeriod(); // true
\Strukt\Today::withDate(when('1959-01-01'))->isValid();
$period->reset(); // restore the real today

String

$value = str('Strukt Commons');

echo $value->toSnake(); // strukt_commons
echo $value->toCamel(); // StruktCommons

$value->startsWith('Strukt');    // true
$value->endsWith('Commons');     // true
$value->contains('Commons');     // true
$value->empty();                 // false
$value->replace('Commons', 'Library');
$value->replaceFirst('S', 'X');
$value->replaceLast('s', 'z');

str('[commons]')->btwn('[', ']'); // commons
str('log')->pad('.')->right(3);   // log...
str('admin@example.com')->is()->email(); // true

Other operations include prepend(), concat(), len(), count(),
split(), slice(), first(), last(), part(), repeat(), toUpper(),
toLower(), replaceAt(), and newline().

Array

arr() returns a chainable wrapper implementing Countable and
IteratorAggregate.

$numbers = arr([1, 2, 2, 3]);

$numbers->sum();     // 8
$numbers->product(); // 12

$numbers->uniq()->values()->yield();   // [1, 2, 3]
$numbers->distinct()->yield();         // [1 => 1, 2 => 2, 3 => 1]

Compose transformations:

$rows = arr([
    ['name' => 'Ada', 'score' => 92],
    ['name' => 'Grace', 'score' => 88],
]);

$names = $rows->column('name')->yield();
$ordered = $rows->order()->desc('score')->yield();
$flat = arr(['user' => ['name' => 'Ada']])->level()->yield();

$upper = arr(['ada', 'grace'])
    ->map(fn (int|string $key, string $value): string => strtoupper($value))
    ->yield();

Predicates and selectors:

arr(['ada', 'grace'])->isof()->strings(); // true
arr([1, 1])->are()->all(1);               // true
arr(['name' => 'Ada'])->is()->map();      // true
arr([1, 2, 3])->only([1, 3])->yield();    // [1, 3]

The wrapper also provides push(), enqueue(), prequeue(), remove(),
merge(), enjoin(), slice(), reverse(), flip(), rehash(), filter(),
each(), diff(), cross(), join(), contains(), has(), skip(),
jump(), stopAt(), and pointer helpers.

Nested arrays can be flattened with optional key prefixes:

arr([
    'user' => [
        'name' => 'Ada',
        'roles' => ['admin', 'author'],
    ],
])->level()->prefix('payload')->yield();

// ['payload.user.name' => 'Ada', 'payload.user.roles.0' => 'admin', ...]

Token queries

$query = token('page:2|tag:php,composer');

$query->has('page'); // true
$query->get('tag');  // ['php', 'composer']

$query->set('sort', 'name')->remove('page');

JSON

$payload = json(['name' => 'Peter', 'active' => true]);

echo $payload->pp();     // pretty JSON

Strukt Console

Documentation-first PHP CLI commands. A structured PHPDoc block on a command
class becomes routing, argument and option parsing, validation, --help output,
command listing, and generated Markdown documentation.

Install

composer require strukt/console

Create a console.php in the consuming project:

<?php

return [
    'commands' => __DIR__.'/src/Command',
    'docs' => __DIR__.'/docs/commands',
];

Defining a command

Implement Strukt\Console\Runtime\CommandInterface and describe the command
with the @command DSL.

<?php

declare(strict_types=1);

namespace App\Command;

use Strukt\Console\Runtime\CommandInterface;

/**
 * @command user:create
 * @description Creates a new application user.
 * @usage user:create <email> [options]
 *
 * @argument email
 * @type string
 * @required
 * @description The user's email address.
 *
 * @option name
 * @type string
 * @default Anonymous
 * @description User's display name.
 *
 * @option admin
 * @flag
 * @description Create the user as an administrator.
 *
 * @option password
 * @type string
 * @required
 * @description Initial password.
 */
final class CreateUser implements CommandInterface
{
    public function execute(array $arguments, array $options): int
    {
        $email = $arguments['email'];
        $name = $options['name'] ?? 'Anonymous';
        $isAdmin = $options['admin'] ?? false;

        return 0;
    }
}

Run it:

vendor/bin/console user:create john@example.com --name="John Doe" --admin --password=secret

Command specification

Tag Purpose
@command Required public command name.
@description Short command description.
@usage Optional explicit usage line.
@argument name Declare a positional argument.
@option name Declare a value option or flag.
@type Argument/option type: string, int, integer, float, bool, boolean.
@required The argument or option must be supplied.
@default Default value.
@enum Comma-separated allowed values.
@flag Declare a boolean switch.
@short Single-character option alias.

Use one tag per line and plain spaces. The DSL is explicit: arbitrary prose is
not guessed or executed.

Runtime contract

interface CommandInterface
{
    public function execute(array $arguments, array $options): int;
}

Return 0 for success. A non-zero value becomes the process exit status.

Help, listing, and docs

vendor/bin/console
vendor/bin/console list
vendor/bin/console user:create --help
vendor/bin/console docs

docs writes Markdown generated from the same command definitions. The command
block is the single source for CLI behaviour, help, validation, and generated
documentation.

Design notes

  • The PHPDoc DSL is intentionally small and deterministic.
  • Types and required fields are validated before execution.
  • Command classes are instantiated through the framework container when used in
    a Strukt application, so constructor dependencies can be declared.
  • Future extensions include attributes, shell completion, command groups,
    aliases, interactive prompts, and richer output formatting.

Strukt Fs

Fast local filesystem, rooted path, and ZIP archive helpers. The package
provides a static Fs API, a rooted Rfs facade, and procedural helpers for
common operations.

Install

composer require strukt/fs

Requires PHP 8.2+ and strukt/base; ZIP operations require ext-zip.

Quick start

require __DIR__.'/vendor/autoload.php';

$files = fs(__DIR__);
$files->touchWrite('storage/app.log', "ready\n");
echo $files->cat('storage/app.log');

$entries = $files->lsr('storage');
$recent = $files->tail('storage/app.log', 20);

Static Fs API

Strukt\Fs\Fs exposes the complete local filesystem API through static
methods.

Existence and file access

use Strukt\Fs\Fs;

Strukt Cache

Typed cache storage with a process-local memory driver, JSON filesystem
persistence, and an optional Memcached backend behind one fluent API.

Install

composer require strukt/cache

Requires PHP 8.2+. The package uses strukt/base for helpers and environment
values, strukt/commons for aliases and configuration, and strukt/fs for

Quick start

The cache() helper opens an in-memory namespace by default.

cache('settings.theme', 'dark');
echo cache('settings.theme'); // dark

use Strukt\Cache\Cache;
use Strukt\Cache\Driver\Memory;

$cache = Cache::make('settings', Memory::class);
$cache->put('theme', 'dark');

echo $cache->get('theme');

Persistent caches must be saved:

use Strukt\Cache\Cache;
use Strukt\Cache\Driver\Fs;

$cache = new Cache('settings', Fs::class);

Drivers

Driver Class Storage
Memory Strukt\Cache\Driver\Memory Current PHP process.
Filesystem Strukt\Cache\Driver\Fs One JSON file per namespace.
Memcached Strukt\Cache\Driver\MemCached A Memcached server.

All drivers implement Strukt\Contract\CacheDriverInterface.

Short driver names are mem/memory, fs, and memc/memcached.

The cache helper

cache(string $filename, mixed $value = null, string $driver = Memory::class): mixed

With no dot in the name, cache() returns a Cache facade:

$cache = cache('settings');
$cache->put('theme', 'dark');

With a dot, the first segment is the namespace and the remainder is a dotted
key:

cache('settings.theme', 'dark', 'fs');
$theme = cache('settings.theme', null, 'fs');

explicitly. memc('sessions') opens a Memcached namespace.

Facade API

use Strukt\Cache\Cache;

$cache = Cache::make('settings', 'mem'); // late-static constructor

$cache->get('user.name');
$cache->exists('user.name');
$cache->remove('user.name');
$cache->empty();
$cache->driver(); // CacheDriverInterface
$cache->save();

consecutive dots throw InvalidArgumentException. A stored null still counts

echo $second->get('user.id'); // 42

Filesystem

atomically through a temporary file.

Memcached

  1. Create or open a namespace.
  2. Read and mutate with exists(), get(), put(), and remove().

local to the driver until save().

Strukt Orm

Managed entities over strukt/ar: an identity map, a unit of work, and result
caching layered on the same Strukt\Ar\Model classes and connection.

The objects are the same entities returned by User::find(); the manager adds
managed behavior for the objects routed through it.

Direct (strukt/ar) Managed (strukt/orm)
Style Immediate, explicit writes. Deferred, batched writes.
Identity One object per call. One object per row.
Writes save()/delete() run at once. persist()/remove() flush on commit().
Reads Query builder per query. Query builder plus result cache.
Use Low-level control. Managed entities on a large workload.

Install

composer require strukt/orm

Requires PHP 8.2+; strukt/ar is pulled in automatically.

Manager

orm() returns the shared manager resolved through the default connection.

use Strukt\Orm\Manager;

Manager::fromEnv('.env', '.env.local');

$sam = orm()->find(User::class, 7);

Manager::for('name') binds a manager to a named connection.
Manager::fromEnv() loads the dotenv files through Strukt\Ar\Connection and
then returns the shared manager.

Identity map and unit of work

find() consults the identity map before touching the database, so a row always
loads into the same instance.

$sam = orm()->find(User::class, 7);
$sam->name = 'Samantha'; // nothing written yet

$draft = new User();
$draft->fill(['name' => 'Ada', 'email' => 'ada@strukt.test']);

orm()->persist($draft);
orm()->remove($sam);
orm()->commit(); // one transaction: insert, update, delete

An untouched entity is not written: a snapshot taken when it was loaded is
compared at commit time, and only drifted columns are saved.

A failed commit rolls the batch back and rethrows the cause. The manager discards
its tracked work, so reload affected rows with find() afterward.

orm()->rollback(); // discard pending work without touching the database

Peek at the identity map without a query:

$sam = orm()->find(User::class, 7);

orm()->lookup(User::class, 7);  // same instance, no round trip
orm()->lookup(User::class, 99); // null

Repositories

query() returns a Repository that proxies the Ar query builder but hydrates
through the identity map, so query results share instances with find().

$admins = orm()->query(User::class)
    ->where('is_admin', 1)
    ->orderBy('name')
    ->get();

$first = orm()->query(User::class)
    ->where('email', $email)
    ->first();

Row results are cached by SQL and bindings, so re-running the same query reuses
the rows. The cache lives in the manager and is emptied by commit(),
rollback(), and clear().

Aggregates such as count() and sum() always read live.

Working with both layers

Installing strukt/orm brings strukt/ar in as a dependency, so both layers use
the same models, tables, and connection. Three behaviours follow:

  1. Ar writes do not invalidate the manager's result cache. Only commit(),
    rollback(), and clear() flush it. A direct User::create() or
    $user->save() bypasses the manager, so a repeated query can serve rows that
    predate the write until the next flush. Aggregates still read live.

  2. One row can exist as two objects. Ar find()/first() materialize fresh
    instances; only objects routed through orm() are identity-mapped. Editing a
    managed entity and then saving it through Ar writes immediately and leaves it
    dirty against its snapshot, so commit() issues a redundant update.
    Ar-deleting a tracked entity makes commit() try the delete again as a
    harmless zero-row change.

  3. Interleaved Ar writes ride the commit's transaction. An Ar save() between
    persist() and commit() uses the same connection, so a failed commit rolls
    it back too.

In practice, pick one path per row or workflow. Route managed rows through
orm(), use strukt/ar directly for one-off or bulk work, and call
orm()->clear() after Ar writes that touch rows also tracked by the manager.
Do not save() or delete() entities you intend to commit().

Tests

The suite runs against an in-memory SQLite connection using the same schema as
strukt/ar and covers the identity map, unit of work, repositories, and result
cache.

Strukt Event

Fast callable events and named command queues. This package is the strukt5
line and a drop-in match for the strukt4/event public API.

Internally it fixes the halt-hook leak in Loop, makes run() exception-safe,
and stops treating array callables such as [$object, 'method'] as argument

Install

composer require strukt/event

Requires PHP 8.2+ and strukt/base. Composer loads src/helpers.php and
installs the global event() and cmd() helpers.

Global helpers

event(string $name, ?callable $function = null): ?Strukt\Event
cmd(string $name, ?array $args = null): mixed

Register and invoke an event:

$login = event(
    'login',
    static fn (string $user, string $password): bool =>
        $user === 'admin' && $password === 'secret',
);

$accepted = $login?->apply('admin', 'secret')->exec();

Calling event() again with the same name replaces the callback but preserves

Event API

Strukt\Event retains a Closure and its ReflectionFunction.

use Strukt\Event;

$event = Event::create(fn (string $name): string => "Hello {$name}");

$event->apply('Ada')->exec();             // Hello Ada
$event->applyArgs(['name' => 'Ada'])->exec();
$event->clear();

$event(); // shorthand for exec()

apply() stores positional arguments. applyArgs() accepts positional or named
keys; named keys use PHP named-argument invocation. Each call replaces the
arguments stored by the previous one. Calling exec() without prepared
arguments invokes the callback with no arguments.

Command API

Strukt\Cmd is the process-local named command registry.

use Strukt\Cmd;

Cmd::add('greet', static fn (string $name): string => "Hello {$name}");
Cmd::add('welcome', ['name' => 'Ada'], static fn (string $name): string => "Hi {$name}");

Cmd::get('greet');   // callable|null
Cmd::exists('greet'); // true
Cmd::ls();            // ['greet', 'welcome']
Cmd::ls('^g');        // ['greet']

Cmd::doc('greet');
Cmd::exec('welcome'); // uses the stored default argument
Cmd::reset();

Ls() filters with a regular-expression body. doc() returns a compact
description from the callback's doc comment, or the command name when none is
available. Executing an unknown command throws InvalidArgumentException.

Loop

Strukt\Loop extends Cmd with an insertion-ordered queue and a repeatable
halt hook.

use Strukt\Loop;

Loop::add('prepare', static function (): void {
    // work
});

Loop::halt(static function (): void {
    // invoked while paused; call Loop::pause(false) to continue
});

Loop::run();

run() executes commands in insertion order and removes them after they run.
While paused, the halt callback is re-invoked each iteration, which makes the
loop a read-eval-print loop. Calling halt() again replaces the previous
terminal callback instead of leaving a stale command behind.

Options:

Loop::run(['alias' => 'worker']); // filter through the base alias map
Loop::run(['limit' => 1000]);     // cap halt iterations

If a command or hook throws, run() removes the terminal command before the
exception escapes, so a failed run leaves no dangling halt command.

Notes

  • Event converts a callable to a Closure and reflection object once.
  • Cmd stores callbacks, defaults, and insertion order in dedicated arrays.
  • Loop re-invokes the halt hook while paused, enabling REPL-style loops.
  • Array callables are recognized as callbacks, not argument arrays.

Process pool

ProcessPool supervises a fixed set of concurrent workers.

$pool = new ProcessPool(3);

Or start one with the helper:

$pool = pool(3, [PHP_BINARY, $workerScript, '--prefix=demo']);

RuntimeException. drain() never blocks on a worker and retains standard
error on each worker. stop() terminates and reaps every worker, returning exit
codes keyed by spawn index.

Process supervisor

ProcessSupervisor composes a pool with a restart policy. A dead worker is
replaced by a fresh copy of the original command in the same slot.

$supervisor = new ProcessSupervisor(3, restartCap: 5, backoff: 0.5);

$supervisor->onExit(static function (int $index, int $exitCode): void {
    printf("worker %d exited with %d\n", $index, $exitCode);
});

$supervisor->start(PHP_BINARY.' '.escapeshellarg($workerScript));

while (true) {
    $supervisor->supervise(static function (int $index, string $line): void {
        printf("worker %d: %s", $index, $line);
    });
    usleep(100000);
}

Or use the helper:

$supervisor = supervisor(3, [PHP_BINARY, $workerScript], restartCap: 5);

Policy:

  • restartCap bounds restarts per slot. -1 never gives up.
  • backoff is the minimum delay before restarting the same slot.
  • onExit() fires whenever a worker is found dead, whether or not it restarts.

supervise() drains output first, then revives dead slots. Introspection includes
restarts($index), totalRestarts, and stop().

Resource lifecycle

Process::run() closes standard input before waiting, drains both output
channels, dispatches pending output, and reaps the child. Captured strings remain
available through the result and process objects after cleanup.

For manual interactive processes:

  1. Call write() as needed.
  2. Call closeInput() when no more input will be sent.
  3. Read output and error.
  4. Call close() or closeAll().

Strukt Queue

A Memcached-backed FIFO message queue with replies. It supports the classic
producer/consumer flow: push a job, pop it, answer with a reply, and wait for the
answer.

The implementation is concurrency-safe: pop() is CAS-guarded, so parallel
workers cannot receive the same message twice.

Requirements

  • PHP 8.2+
  • memcached extension and libmemcached
  • a running Memcached server, default 127.0.0.1:11211

Install

composer require strukt/queue

The package depends on strukt/base, strukt/console, and strukt/process.
The kqueue binary is installed into vendor/bin/.

Quick start

use Strukt\Queue;

$id = $queue->push('jobs', ['user' => 7, 'type' => 'export']);

// in a worker
$job = $queue->pop('jobs', $id);
$queue->reply('jobs', $id, 'exported-42.pdf');

// in the caller
$reply = qwait('jobs', $id, 30);

Features

  • FIFO delivery with monotonic, never-reused ids.
  • Exactly-once handoff under parallel workers.
  • Replies for request/response jobs.
  • Namespaces through the prefix option.
  • Loud failures: constructor throws, failed pushes throw, waits time out.
  • Rescue of expired or missing slots.
  • Crash redelivery through Strukt\Queue\Supervisor.

Strukt\Queue is the complete surface.

Strukt Rules

Data-driven validation rules, a parser, a registry, and a value validator.

Every built-in rule has a declaration in src/Strukt/Rules/Spec/ describing its
arity, parameter format, failure message, and bail behaviour. Those
specifications compile into one table read by the shared engine, so parsing,
messages, and bail behaviour cannot drift apart.

This package has no runtime dependencies and powers strukt/form.

Install

composer require strukt/rules

Validating values

Validator takes field values and a rules definition keyed by field name. Each
entry is a pipe-separated string or a list of rule tokens.

use Strukt\Rules\Validator;

$errors = (new Validator())->validate(
    ['age' => 12],
    ['age' => 'required|integer|min:18'],
);

// ['age' => ['Age must be at least 18.']]

The standalone helper is equivalent:

$errors = check(
    ['age' => 12],
    ['age' => 'required|integer|min:18'],
);

Failures are collected per field in declaration order.

Rules

Presence

Rule Passes when
required Value is not null, '', or [].
filled Same check as required.
nullable Value is not null.

0 and false count as present. A non-required field with an absent value skips
its remaining rules.

Types

Rule Passes when
string Value is a string.
integer An int, or a string of digits. 5.5 and 1e3 fail.
numeric is_numeric.
boolean Bool, or 0/1/true/false/on/off/yes/no.
array Value is an array.

Formats

Rule Passes when
email FILTER_VALIDATE_EMAIL.
url FILTER_VALIDATE_URL.
uuid RFC 4122 UUID.
ip FILTER_VALIDATE_IP.
date A real date in the given format, default Y-m-d.
regex The pattern matches.
alpha Letters only, across scripts.
alpha_num Letters and numbers, across scripts.

date rejects invalid calendar dates rather than rolling them over.

'born_on' => 'date',       // Y-m-d
'shipped' => 'date:m/d/Y', // 02/29/2024

regex accepts patterns with or without delimiters and keeps commas inside a
pattern.

'zip'    => 'regex:^\d{5}$',
'ssn'    => 'regex:/^\d{3}-\d{4}$/',
'csv_id' => 'regex:^\d{3},\d{4}$',

Size

Rule Passes when
min:n Number is at least n.
max:n Number is at most n.
between:min,max Number is within the inclusive range.
length:n String is exactly n characters.
min_length:n String is at least n characters.
max_length:n String is at most n characters.
min_count:n Array has at least n items.
max_count:n Array has at most n items.

min compares numbers, min_length counts characters with mb_strlen, and
min_count counts items.

Sets and fields

Rule Passes when
in:a,b,c Value is one of the options.
not_in:a,b,c Value is none of the options.
same:field Value equals the named field.
different:field Value differs from the named field.

in and not_in compare loosely, so a submitted '2' matches an option list
containing 2.

Bailing

Shape-guarding rules such as required, integer, and array stop the field
when they fail, so dependent checks do not add a second confusing message.

'age' => 'required|integer|min:18'

For age => 'not a number', only Age must be an integer. is reported.

Messages

Messages use a readable field label and the rule's wording. email_address
becomes Email address; min_length:8 on name becomes
Name must be at least 8 characters.

Override a message per rule or per field/rule:

use Strukt\Rules\Messages;
use Strukt\Rules\Validator;

$validator = new Validator(null, new Messages([
    'email.required' => 'We need an email address to reach you.',
    'min_length' => ':field is too short, use at least :0 characters.',
]));

An override is used as written and may use :field, :0, :1, :list, and
:format.

Custom rules

Implement RuleInterface; a rule receives the value and a FieldSource for
reading sibling fields.

use Strukt\Rules\Contract\FieldSource;
use Strukt\Rules\Contract\RuleInterface;

final class AfterRule implements RuleInterface
{
    public function __construct(
        private readonly string $field,
        private readonly string $other,
    ) {
    }

    public function passes(mixed $value, FieldSource $fields): bool
    {
        $other = $fields->value($this->other);

        return is_string($value) && is_string($other) && $value > $other;
    }

    public function message(): string
    {
        return ucfirst($this->field).' must be later than '.$this->other.'.';
    }

    public function bails(): bool
    {
        return false;
    }
}

Register globally or pass a private registry:

use Strukt\Rules\RuleRegistry;
use Strukt\Rules\Validator;

RuleRegistry::shared()->extend(
    'after',
    fn (string $field, array $params) => new AfterRule($field, $params[0]),
);

$validator = new Validator(RuleRegistry::shared());

extend() accepts a rule instance or a factory called with the field name and
parsed parameters. Built-in names cannot be replaced. A misspelled rule name
throws Strukt\Rules\Exception\UnknownRule with the available rules.
