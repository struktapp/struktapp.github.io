Strukt

A PHP framework and ecosystem built around modular packages. Strukt4 uses tagged releases, a PSR-11 container, and a layered package architecture.

Strukt Base

Strukt Base



Typed runtime foundations for Strukt packages. Base provides process-local
aliases and environment values, cached reflection wrappers, helper
registration, a small runtime exception type, a PSR-11 dependency
container exposed through app(), and Symfony-backed dd()/dump() debugging
helpers.

Requirements

  • PHP 8.2 or newer
  • psr/container ^1.1 || ^2.0
  • symfony/var-dumper ^7.0 || ^8.0

Installation

composer require strukt/base

Composer loads src/helpers.php automatically. The package therefore exposes
its global helpers after the normal Composer autoloader has been required:

require __DIR__ . '/vendor/autoload.php';

alias('user', App\User::class);
env('APP_ENV', 'production');

$user = ref(App\User::class)->makeArgs(['Ada'])->getInstance();

Global helpers

The helpers are conditionally defined so multiple Strukt packages can share a
process without redeclaring the same function. The base helper registry keeps
the names that were successfully installed.

helper()

helper(?string $package = null): Strukt\Helper|array|null

Reads the helper registry or selects a package for subsequent registrations.
Passing null, packages, pkg, or pkgs lists package names. Passing a package
name returns its registered helper names when the package is loaded; an
unknown package is selected and initialized.

helper();          // ['base', ...]
helper('base');    // ['helper_add', 'is_map', ...]
helper('event');   // selects the event package when it is loaded

helper_add()

helper_add(string $functionName): bool

Registers a helper name for the package selected by helper(). It returns true
only when the name is available to define. Package helper files use this check
before declaring each global function.

is_map()

is_map(array $value): bool

Returns true for a non-empty associative array and false for an empty or
list-shaped array.

alias()

alias(?string $alias = null, ?string $longName = null): array|string|null

Registers, reads, or lists aliases:

alias('user', App\User::class); // registers and returns the target
alias('user');                  // returns App\User::class
alias();                        // returns alias => target pairs
alias('user*');                 // returns matching alias => target pairs

Registering an existing alias throws LogicException. Empty names throw
InvalidArgumentException.

env()

env(string $key, string|int|bool|null $value = null): string|int|bool

Stores a process-local value when value is supplied, then returns the value.
Missing keys throw Strukt\Raise.

env('APP_ENV', 'production');
$environment = env('APP_ENV');

ref()

ref(string|object|callable $value): mixed

Creates a Ref wrapper for a class name or object, or a FunctionReference for a
callable. It returns null when a string is not a class and the value is not
callable.

raise()

raise(string $message, int $code = 500): never

Throws Strukt\Raise immediately and records the message in the process-local
error list.

timezone()

timezone(?string $locale = null): string|false

Returns the configured PHP timezone. When the current configuration is UTC
and a locale is supplied, it changes the default timezone and returns that
locale. Without a locale it only reads the current value.

negate() and notnull()

negate(bool $value): bool
notnull(mixed $value): bool

negate() inverts a boolean. notnull() tests for strict non-nullness.

dd() and dump()

dd() and dump() come from the symfony/var-dumper dependency and use
Symfony's VarDumper for their output; dd() dumps each value and exits with
status 1.

dd(mixed ...$values): never
dump(mixed ...$values): mixed

symfony/var-dumper declares these globals first, so base normally defers to
them. Base also declares a guarded dd() fallback (using the same VarDumper)
that only takes effect when symfony's functions file was not loaded — for
example under PsySH, whose bundled autoloader deduplicates the shared file
identifier and skips the project's dump.php.

app()

app(?string $abstract = null, array $parameters = []): mixed

Resolves against the shared dependency container, or returns the container
itself. With no argument it returns the process-wide container; with an
identifier it resolves a binding or autowires the class; with parameters it
builds the class using the named constructor overrides.

app();                                    // the shared container
app(Cache::class);                        // binding or autowired class
app(Controller::class, ['id' => 7]);      // built with overrides

Helper inventory

The base package exposes these global helper functions:

helper, helper_add, is_map, alias, app, env, ref, raise, timezone,
negate, notnull

dd() and dump() are also available (via symfony/var-dumper). Because
symfony declares them first, they are normally not registered in base's helper
registry; dd is registered only when base's guarded fallback is the one that
defines it.

helper() is the registry bootstrap function, so the registry's base list starts
with helper_add and then records the remaining conditionally-defined helpers.

The class APIs below are the typed equivalents behind those helpers.

Alias API

Strukt\Alias stores short names for classes, commands, and events.

Alias::set(string $alias, string $longName): string
Alias::get(string $alias): ?string
Alias::exists(string $alias): bool
Alias::ls(?string $startsWith = null): array
Alias::reset(): void

set() registers an alias once and throws when the alias or target is empty or
already registered. ls() returns alias names, optionally restricted to a
prefix. reset() clears the process-local store.

Environment API

Strukt\Env stores typed values in memory; it does not mutate PHP's process
environment.

Env::withFile(string $path = '.env'): void
Env::has(string $key): bool
Env::get(string $key): string|int|bool
Env::set(string $key, string|int|bool $value): void
Env::reset(): void

withFile() accepts blank lines, # and // comments, an optional export prefix,
quoted values, and values containing =. The strings true and false are loaded
as booleans. A missing or unreadable file throws InvalidArgumentException;
get() throws Strukt\Raise for an unknown key.

Reflection API

Strukt\Ref caches ReflectionClass objects for the lifetime of the process.
Use resetCache() when a long-running process needs to discard that cache.

Ref::func(callable $function): FunctionReference
Ref::createFrom(object $instance): Ref
Ref::create(string $className): Ref
Ref::resetCache(): void

Class and instance references expose:

$reference->method(string $name): MethodReference
$reference->props(): array
$reference->prop(string $name): PropertyReference
$reference->ref(): ReflectionClass
$reference->getInstance(): ?object
$reference->readyMade(object $instance): object
$reference->make(mixed ...$args): Ref
$reference->makeArgs(array $args): Ref
$reference->noMake(): Ref

make() and makeArgs() construct an object; noMake() creates one without
running its constructor. Instance methods and properties require an instance,
which can be supplied with createFrom(), readyMade(), or a construction
method.

FunctionReference

$reference->ref(): ReflectionFunction
$reference->invoke(mixed ...$args): mixed

MethodReference

$reference->ref(): ReflectionMethod
$reference->getClosure(): Closure
$reference->invoke(mixed ...$args): mixed

PropertyReference

$reference->ref(): ReflectionProperty
$reference->set(mixed $value): void
$reference->get(): mixed

These wrappers also work with non-public members through PHP reflection.

Helper registry API

Strukt\Helper tracks helper names per package:

Helper::__construct(string $package)
Helper::create(string $package): Helper
Helper::singleton(): ?Helper
$registry->register(string $functionName): bool
$registry->get(string $package): ?array
$registry->listPackages(): array
Helper::reset(): void

create() selects the shared registry and package. register() is intended for
conditional helper declarations and refuses names that already exist as global
functions.

Raise API

Strukt\Raise is the runtime exception used by the helpers.

new Raise(string $message, int $code = 500)
Raise::errors(): array
Raise::reset(): void

Each exception records its message in Raise::errors(). reset() clears the
process-local error history.

Container API

Strukt\Container\Container is a small PSR-11 container with constructor
autowiring. It owns the process-wide instance returned by app() and by the
framework container() helper.

Container::getInstance(): Container
Container::setInstance(?Container $container): ?Container

$container->set(string $id, callable $factory): static      // shared
$container->factory(string $id, callable $factory): static  // per resolve
$container->instance(string $id, mixed $value): static      // prebuilt
$container->alias(string $alias, string $id): static        // pointer
$container->get(string $id): mixed
$container->has(string $id): bool
$container->make(string $class, array $parameters = []): object

get() returns a binding or autowires the class; make() reflects the
constructor and resolves each parameter from a named override, then the
container, then a default. Missing identifiers throw
Strukt\Container\NotFoundException; failed construction throws
Strukt\Container\ContainerException (both PSR-11 exceptions).

use Strukt\Container\Container;

$container = new Container();
$container->set(Mailer::class, fn (Container $c) => new Mailer($c->get(Transport::class)));

$mailer = $container->get(Mailer::class);              // shared
$user = $container->make(User::class, ['id' => 7]);    // autowired + override

The container requires psr/container, which supplies the two PSR-11
interfaces it implements.

Performance notes

  • Class reflection objects are cached by Ref.
  • Helpers avoid repeated registration and are only defined when their names
    are available.
  • Environment values and aliases use in-memory arrays for constant-time
    lookup.
  • FunctionReference and the method/property wrappers retain their native
    reflection object instead of rebuilding it for every call.

Strukt Commons

Strukt Commons





Strukt Commons is a small, self-contained PHP utility library. It provides
chainable array and string values, dot-separated collections, date ranges,
token queries, registries, message stacks, JSON helpers, and common global
functions.

The package requires PHP 8.2 or newer and depends on strukt/base, which
provides the lowest-level primitives (alias(), raise(), app(), and the
helper registry). Optional integrations such as Ramsey UUID and Symfony's
English inflector are used when they are already installed, while standalone
fallbacks remain available.

Installation

Install the package through Composer:

composer require strukt/commons

When working from this repository, install the development dependencies and
run the test suite:

composer install
composer test

Composer loads the Strukt\ namespace from src/Strukt and registers the
global helpers from src/helpers.php.

require __DIR__ . '/vendor/autoload.php';

Usage

Collection

collect() creates a mutable collection whose values can be read and written
through dot-separated paths.

$contact = collect([]);
$contact->set('mobile', '+2540770123456');
$contact->set('work-phone', '+2540202345678');

$user = collect([]);
$user->set('contacts', $contact->yield());

echo $user->get('contacts.mobile');
// +2540770123456

$user->exists('contacts.mobile');
// true

$user->remove('contacts.work-phone');
$user->keys('contacts');
// ['mobile']

The same dot-path behavior is available through the dot(), attach(), and
detach() helpers:

$data = [
    'user' => [
        'firstname' => 'Gene',
        'surname' => 'Wilder',
        'db' => [
            'config' => [
                'username' => 'root',
                'password' => '_root!',
            ],
        ],
    ],
];

echo dot('user.db.config.username', $data);
// root

attach('user.db.config.host', $data, 'localhost');
detach('user.db.config.password', $data);

Value Objects

Value objects expose their raw value through yield(). Most transformations
return a new wrapper so calls can be chained without changing the original.

$name = str('user name')->toSnake();
echo $name->yield();
// user_name

$items = arr(['first', 'second'])->push('third');
print_r($items->yield());

Value Objects

DateTime

when() creates a Strukt\DateTime value. It accepts normal PHP date strings,
relative expressions, and Unix timestamps.

$start = when();
$end = when('+30 days');
$random = $start->rand($end);

echo $random;

$end->gt($start);
// true

$start->btwn($start, $end);
// true

$start->reset();
$start->last();
echo $start;

Date values also support gte(), gt(), lte(), lt(), equals(),
same(), btwn(), clone(), and the relative when() description. same()
compares calendar dates, while equals() compares the complete instant.

Today (Date Influence)

period() controls an inclusive date range and can provide a simulated current
day. This is useful for deterministic application behavior and tests.

$period = period();
$period->create(when('1900-01-01'), when('1963-12-31'));
$period->reset(when('1960-03-23'));

$fakeToday = today();
echo $fakeToday->format('Y-m-d');
// 1960-03-23

\Strukt\Today::withDate(when('1959-01-01'))->isValid();
// true

$period->reset();

today() follows the simulated day until the period controller is reset.
Strukt\Today::makePeriod(), Strukt\Today::reset(),
Strukt\Today::hasPeriod(), and Strukt\Today::getState() are available
when direct static access is preferred.

String

str() returns a chainable Strukt\Str wrapper for common byte-oriented
string operations.

$value = str('Strukt Commons');

echo $value->toSnake();
// strukt_commons

echo $value->toCamel();
// StruktCommons

$value->startsWith('Strukt');
// true

$value->replace('Commons', 'Library');
// Strukt Library

str('[commons]')->btwn('[', ']');
// commons

str('log')->pad('.')->right(3);
// log...

str('admin@example.com')->is()->email();
// true

Other string operations include prepend(), concat(), len(), count(),
split(), slice(), toUpper(), toLower(), endsWith(), contains(),
replaceAt(), replaceFirst(), replaceLast(), first(), last(),
part(), repeat(), and newline().

Array

arr() returns a chainable Strukt\Arr wrapper. It implements both
Countable and IteratorAggregate and supports list and associative arrays.

$numbers = arr([1, 2, 2, 3]);

echo $numbers->sum();
// 8

echo $numbers->product();
// 12

print_r($numbers->uniq()->values()->yield());
// [1, 2, 3]

print_r($numbers->distinct()->yield());
// [1 => 1, 2 => 2, 3 => 1]

Array transformations can be composed:

$rows = arr([
    ['name' => 'Ada', 'score' => 92],
    ['name' => 'Grace', 'score' => 88],
]);

$names = $rows->column('name')->yield();
$ordered = $rows->order()->desc('score')->yield();
$flat = arr(['user' => ['name' => 'Ada']])->level()->yield();

$upper = arr(['ada', 'grace'])
    ->map(fn (int|string $key, string $value): string => strtoupper($value))
    ->yield();

Useful predicates and selectors include:

arr(['ada', 'grace'])->isof()->strings();
// true

arr([1, 1])->are()->all(1);
// true

arr(['name' => 'Ada'])->is()->map();
// true

arr([1, 2, 3])->only([1, 3])->yield();
// [1, 3]

array_values(arr([3, 1, 2])->sort()->asc());
// [1, 2, 3]

The wrapper also provides push(), enqueue(), prequeue(), remove(),
merge(), enjoin(), slice(), reverse(), flip(), rehash(), map(),
filter(), each(), diff(), cross(), join(), contains(), has(),
skip(), jump(), stopAt(), will(), and pointer helpers such as
first(), current(), next(), sibling(), and last().

Nested arrays can be flattened with optional prefixes:

$flat = arr([
    'user' => [
        'name' => 'Ada',
        'roles' => ['admin', 'author'],
    ],
])->level()->prefix('payload')->yield();

// [
//     'payload.user.name' => 'Ada',
//     'payload.user.roles.0' => 'admin',
//     'payload.user.roles.1' => 'author',
// ]

Others

Token Query

Token queries read and write compact key:value|key:value strings.

$query = token('page:2|tag:php,composer');

$query->has('page');
// true

$query->get('tag');
// ['php', 'composer']

$query->set('sort', 'name')->remove('page');
echo $query->yield();
// tag:php,composer|sort:name

Use tokenize() when an associative array should be serialized directly:

echo tokenize([
    'page' => 2,
    'tag' => ['php', 'composer'],
]);
// page:2|tag:php,composer

Stack / Messages

stack() records messages in a bounded, process-local stack. The default limit
is ten messages.

\Strukt\Stack::clear();

$message = stack('User was not found');
$message->add('A retry was scheduled');

$messages = \Strukt\Stack::get();
$messages->yield();

$filtered = \Strukt\Stack::get('/retry/');
$filtered->yield();

\Strukt\Stack::limit(20);

Strukt\Stack::clear() removes all messages, and Strukt\Stack::get() returns an Arr
wrapper so the normal array operations remain available.

Json

json() provides a small wrapper around native JSON encoding and decoding.

$payload = json([
    'name' => 'Peter',
    'active' => true,
]);

echo $payload->pp();

$encoded = $payload->encode();
$decoded = json($encoded)->decode();

json($encoded)->valid();
// true

Encoding and decoding use JSON_THROW_ON_ERROR, so malformed JSON and values
that cannot be encoded raise JsonException.

Registry, Configuration, and Helpers

The process-local registry stores dot-separated values and is available through
reg() or Registry:

reg('user.name', 'Ada');
echo reg('user.name');
// Ada

echo config('app.name');
// payroll

echo format('date', when('2024-01-01'));
// 2024-01-01

echo plural('story');
// stories

echo singular('stories');
// story

echo uuid();

Additional helpers include provider() for invoking provider registration. The
low-level primitives alias(), is_map(), notnull(), negate(), and
raise() are provided by the required strukt/base package.

Strukt Contract

Strukt Contract

Zero-dependency interfaces for HTTP, authentication, forms, and service
providers, plus small reference implementations of the user, session, and auth
contracts.

This is the foundational Strukt package: it requires nothing but PHP, so any
other package or application can depend on it without pulling a runtime.

Install

composer require strukt/contract

Contracts

Contract Purpose
Strukt\Contract\UserInterface An authenticated principal. Nullable throughout, password is write-only.
Strukt\Contract\AuthInterface The gate that resolves the current principal.
Strukt\Contract\MiddlewareInterface One link in the HTTP pipeline.
Strukt\Contract\FormInterface Field definitions, submitted values, and validation state.
Strukt\Contract\ProviderInterface Container bindings contributed by a service provider.
Strukt\Contract\Http\RequestInterface An inbound request: method, uri, headers, params, files, user.
Strukt\Contract\Http\ResponseInterface A response under construction: status, headers, body, send.
Strukt\Contract\Http\SessionInterface Per-client state between requests, including flash data.
Strukt\Contract\Http\DownloadInterface A payload offered as an attachment or inline.
Strukt\Contract\Http\UploadedFileInterface A file received through a multipart form.

Two design rules hold across all of them:

  • No contract names a concrete class. A middleware returns a
    ResponseInterface, never a specific response type, so implementations stay
    substitutable.
  • Every accessor is honest about null. A guest is a valid state, so user
    and request accessors return ?T rather than throwing or lying.

Implementations

Strukt\User, Strukt\Session, and Strukt\Auth are dependency-free
reference implementations. They are the default wiring, not the only option:
any type satisfying the contracts can be injected.

User

use Strukt\User;

$user = new User(id: '7', username: 'pitsolu', email: 'pitsolu@gmail.com');

$user->getUsername();          // 'pitsolu'
$user->get('id');              // '7'
$user->has('email');           // true
$user->toArray();              // ['id' => '7', 'username' => 'pitsolu', 'email' => ...]

The password is write-only. It is never returned by a getter, is not
addressable through get(), and never appears in toArray():

$user = new User(password: password_hash('secret', PASSWORD_BCRYPT));

$user->hasPassword();          // true
$user->verifyPassword('secret'); // true
$user->verifyPassword('wrong');  // false
$user->get('password', 'leaked'); // 'leaked' — never the real value

Use credentials() when the bearer token is genuinely required, and treat the
result as sensitive.

Session

use Strukt\Session;

$session = new Session();

$session->set('theme', 'dark');
$session->get('theme');        // 'dark'
$session->has('theme');        // true

$session->flash('notice', 'saved');
$session->getFlash('notice');  // 'saved' — consumed on read

has() reports key presence, so a key holding null is still present:

$session->set('nullable', null);

$session->has('nullable');                   // true
$session->get('nullable', 'fallback');       // null

Auth

Auth receives its session by injection rather than resolving a global
container, so it is constructible anywhere — a test, a CLI process, or a host
runtime.

use Strukt\Auth;
use Strukt\Session;
use Strukt\User;

$auth = new Auth(new Session());

$auth->guest();                 // true
$auth->login(new User(id: '7', username: 'pitsolu'));
$auth->check();                 // true
$auth->id();                    // '7'
$auth->logout();                // clears the user and the session keys

A fresh instance resumes an existing session, so the principal survives
across requests:

$auth->login(new User(id: '7', username: 'pitsolu'));

(new Auth($session))->user()?->getUsername();  // 'pitsolu'

login() rejects a user with neither an id nor a username, because such a
record cannot be attributed to a session.

Middleware

use Strukt\Contract\Http\RequestInterface;
use Strukt\Contract\Http\ResponseInterface;
use Strukt\Contract\MiddlewareInterface;

final class Authenticate implements MiddlewareInterface
{
    public function process(RequestInterface $request, ResponseInterface $response, callable $next): ResponseInterface
    {
        if ($request->user() === null) {
            return $response->setStatus(401);
        }

        return $next($request, $response);
    }
}

Returning without calling $next short-circuits the chain, which is how a
middleware rejects a request before it reaches the handler.

Installation

Quick start

Console

A bin/strukt binary is published to your vendor/bin:

vendor/bin/strukt list
vendor/bin/strukt help module:make
vendor/bin/strukt cache:clear

A development-only bin/xhttp binary is also published. It dispatches a request
through your application in-process, no web server required:

vendor/bin/xhttp GET /hello/ada
vendor/bin/xhttp POST /login email=ada@example.com password=secret

Modules and routers

A module groups the application facets beneath one namespace:

final class AuthModule extends \Strukt\Framework\Contract\Module
{
    protected string $alias = 'auth';
}

Routers carry method annotations that the Application turns into routes on the
strukt4 router:

final class Login extends \Strukt\Framework\Contract\Router
{
    /**
     * @Route(/auth/login)
     * @Method(POST)
     * @Form(Authentication)
     * @Middleware(sess)
     */
    public function login(\Strukt\Http\Request $request)
    {
        //
    }
}

Register a module and dispatch:

$app = Application::make();
$app->register(new AuthModule());
$app->handle();       // returns a ResponseInterface
// or
$app->run();          // sends the response

Facets are indexed in the nr registry (nr.<alias>.<facet>.<name>) and can be
resolved through the core() helper:

core('auth.ctr.Login', ['request' => request()]);

Serving the application

app:make scaffolds a front controller (index.php) and app:reload generates
lib/App/Loader.php. app:exec boots the built-in server with index.php as
the router script, so every URL dispatches through the application:

vendor/bin/strukt app:make payroll
vendor/bin/strukt app:reload
vendor/bin/strukt app:exec
# http://127.0.0.1:8080

Application namespaces resolve at runtime through Strukt\Framework\Autoload
(App\ -> lib/, and each first-level directory under app/src such as

Strukt Router

Strukt Router

A typed HTTP router with parameter matching, a middleware pipeline, reflection
resolved actions, and form validation — built on the strukt4 packages.

Routes are declared against patterns such as /user/{id:int}, matched by a
compiled regex with typed parameter extraction, guarded by a middleware chain,
and dispatched by reflecting the action callable to inject the request, the
response, services, or a validated form.

use Strukt\Contract\Http\RequestInterface;

$router = new Strukt\Router\Router();

$router->get('/', fn () => 'home');
$router->get('/user/{id:int}', fn (int $id) => "user[{$id}]");
$router->post('/login', fn (RequestInterface $request, Strukt\Contract\FormInterface $form) => $form->value('email'))
    ->form(LoginForm::class);

$response = $router->kernel()->handle($request);
$response->send();

Routing

Use one verb method per route, or any() to accept every common method.
get(), post(), put(), patch(), delete(), options(), and head() all
share the same shape.

$router->get('/list', fn () => 'list');
$router->post('/save', fn () => 'saved');
$router->any('/hook', fn () => 'any method');

Groups

Wrap a callback with group() to share a path prefix.

$router->group('/api/v1', function (Strukt\Router\Router $router) {
    $router->get('/users', fn () => 'users');
    $router->get('/users/{id:int}', fn (int $id) => "user[{$id}]");
});

Named routes

name() assigns a route name for reverse generation with path().

$router->get('/user/{id:int}', fn (int $id) => "user[{$id}]")->name('user.show');

$router->path('user.show', ['id' => 7]); // '/user/7'

Route options — name(), middleware(), permissions(), requiresAuth(),
form(), and defaults() — mutate the registered route fluently and can be
stacked in any order.

Parameters

A pattern is slash separated segments. A segment may be literal, a plain
placeholder, a typed placeholder, a wildcard, or an optional placeholder.

Pattern Matches Type
{name} any segment string
{id:int} digits int
{price:float} decimal float
{on:bool} true / false bool
{word:alpha} letters string
{key:alphanum} letters, digits, _, - string
{slug} slug words string
{on:date} YYYY-MM-DD string
{id:uuid} UUID string
{rest:*} remaining segments string 
$router->get('/user/{id:int}', fn (int $id) => "user[{$id}]");
$router->get('/blog/{year:int}/{?month:int}', fn (int $year, ?int $month = null) => '');
$router->get('/files/{rest:*}', fn (string $rest) => $rest);

Matched values are cast, so {id:int} hands an int to the action. An unknown
type and a missing required placeholder both throw. Reverse generation through
uri() or Router::path() respects the same rules and route defaults.

Middleware

Global middleware runs before every route; route middleware runs after that.
Definitions may be a registered name, a class, an object, or a callable.

$router->middleware(TraceMiddleware::class);
$router->get('/admin', fn () => 'admin')->middleware('auth', 'authz');

Three names are registered out of the box:

Name Class Purpose
sess Middleware\Session Attach the session store to the request.
auth Middleware\Authentication Resolve and bind the current user.
authz Middleware\Authorization Enforce required permissions.

Middleware resolves through constructor injection: a middleware class declares
the services it needs (SessionInterface, AuthInterface, a $verify or
$permissions callable) and the router supplies them from the per-request
service map.

Authentication and permissions

verify() and permissions() configure how users and grants are resolved.
Routes opt in with requiresAuth() and permissions([...]).

$router->session(fn (): SessionInterface => new Strukt\Http\Session\Native());
$router->verify(fn (SessionInterface $session): ?UserInterface => $session->get('email')
    ? new Strukt\User(email: $session->get('email'))
    : null);
$router->permissions(fn (?UserInterface $user): array => $user?->getEmail() === 'admin@example.com'
    ? ['admin']
    : []);

$router->get('/dashboard', fn (RequestInterface $request) => $request->user()?->getEmail() ?? 'guest')
    ->requiresAuth();

$router->get('/admin', fn () => 'admin')
    ->requiresAuth()
    ->permissions(['admin']);

A missing user on an authenticated route stops with a 401; a user without the
required permission receives a 403.

Forms

Attach a Strukt\Form\Form class with form(). The router submits the request
values and validates before the action runs; a failing validation answers with
a 422 carrying the errors as JSON.

$router->post('/login', fn (Strukt\Contract\FormInterface $form) => 'hi ' . $form->value('email'))
    ->form(LoginForm::class);

Responses

An action may return a string (body), an array (JSON), a ResponseInterface,
or null. Use the response() helper for typed responses and redirects:

$router->get('/home', fn () => response()->redirect('/home'));
$router->get('/data', fn () => response()->json(['ok' => true]));
$router->get('/file', fn () => download('/tmp/report.pdf', 'report.pdf'));

The kernel maps exceptions to HTTP errors: 404 for an unknown path, 405 with an
Allow header for a bad method, 422 for failed form validation, and 401 or 403
for the auth gates.

This is the strukt5 line. The public API is a drop-in match for

Event API

Strukt\Event retains a Closure and its ReflectionFunction. Use it when a
callable needs to be prepared once and invoked repeatedly.

new Event(callable $event)
Event::create(callable $event): Event
$event->apply(mixed ...$args): Event
$event->applyArgs(array $args): Event
$event->clear(): Event
$event->ref(): ReflectionFunction
$event->exec(): mixed
$event(): mixed

apply() stores positional arguments. applyArgs() accepts either positional
integer keys or named string keys. Named keys are expanded with PHP named
argument invocation:

$event = Event::create(
    static fn (string $name, int $age): string => "$name:$age",
);

$event->applyArgs(['name' => 'Ada', 'age' => 37])->exec();
// Ada:37

Calling apply() or applyArgs() replaces arguments stored by an earlier call.
clear() drops them again. Calling exec() without prepared arguments invokes the
callback with no arguments. An Event is invokable, so $event() is shorthand
for $event->exec().

Command API

Strukt\Cmd is the process-local named command registry.

add()

Cmd::add(string $name, callable $callback): void
Cmd::add(string $name, array $defaultArgs, callable $callback): void

The first form registers a callback without defaults. The second stores
default positional or named arguments that exec() uses when no explicit
arguments are supplied. Arguments may also follow the callback
(Cmd::add($name, $callback, $defaultArgs)). Empty names, argument lists
without a callback, and non-callable definitions throw
InvalidArgumentException. Array callables such as [$object, 'method'] are
recognised as callbacks, not as argument arrays.

Cmd::add(
    'greet',
    ['name' => 'Ada'],
    static fn (string $name): string => "Hello $name",
);

get()

Cmd::get(string $name): ?callable

Returns a registered callback or null.

ls()

Cmd::ls(?string $filter = null): array

Returns command names in insertion order. When filter is supplied, it is used
as a regular-expression body and wrapped in slash delimiters. An invalid
regular expression throws InvalidArgumentException.

Cmd::ls();          // ['greet', 'login']
Cmd::ls('^g');      // ['greet']

exists(), doc(), exec(), and reset()

Cmd::exists(string $name): bool
Cmd::doc(string $name): string
Cmd::exec(string $name, ?array $args = null): mixed
Cmd::reset(): void

doc() extracts the callback's doc comment and returns a compact description,
caching it until the command changes; for an undocumented or unknown command it
returns the command name. exec() uses explicit arguments when provided,
otherwise the defaults from add(). Executing an unknown command throws
InvalidArgumentException. reset() clears callbacks, defaults, cached
descriptions, and insertion order.

Loop API

Strukt\Loop extends Cmd with an insertion-ordered queue and a repeatable halt
hook.

Loop::halt(callable $callback): void
Loop::pause(bool $halt = true): void
Loop::isHalted(): bool
Loop::run(array $options = []): void
Loop::reset(): void

Register work, then run it:

Loop::add('prepare', static function (): void {
    // work
});

Loop::halt(static function (): void {
    // invoked while paused; call pause(false) to continue
});

Loop::run();

run() executes commands in insertion order and removes them after they run.
While paused (Loop::pause(true) or after halt()), the halt callback registered
via halt() is re-invoked on each iteration until pause(false) is called, which
makes the loop a read-eval-print loop. Calling halt() again replaces the
previous terminal callback rather than leaving a stale command behind.

run() accepts two options:

  • alias: filters the queue through the base package's wildcard alias map:

    Loop::run(['alias' => 'worker']);

  • limit: caps the number of halt iterations, useful as an escape hatch for
    non-interactive runs. It is unbounded by default so REPLs keep working.

    Loop::run(['limit' => 1000]);

If a command or hook throws, run() still removes the terminal command before
letting the exception escape, so a failed run never leaves a dangling halt
command in the registry.

Performance notes

  • Event converts a callable to Closure and ReflectionFunction once.
  • Event execution invokes the retained Closure directly.
  • Cmd stores callbacks, defaults, and insertion order in dedicated arrays.
  • Cmd caches doc() descriptions and invokes callbacks directly, without
    creating an Event wrapper.
  • Loop re-invokes the halt hook while paused, enabling REPL-style loops.

Strukt Cache


Typed cache storage for PHP 8.2 and later. Strukt Cache provides fast
process-local memory storage, JSON filesystem persistence, and an optional
Memcached driver behind one fluent API.

This package is the Strukt 3 rewrite of 'strukt2/cache'. It preserves the
cache and memc helpers, dotted keys, fluent driver methods, and explicit
save() lifecycle while improving validation, filesystem safety, JSON errors,
driver resolution, and documentation.

Installation

composer require strukt/cache

The package uses:

  • strukt/base for the helper registry and environment values;
  • strukt/commons for application aliases and configuration;
  • strukt/fs for filesystem operations.

Quick start

The cache helper opens an in-memory namespace by default:

<?php

cache('settings.theme', 'dark');

echo cache('settings.theme'); // dark

For an explicit fluent facade:

use Strukt\Cache\Cache;
use Strukt\Cache\Driver\Memory;

$cache = Cache::make('settings', Memory::class);
$cache->put('theme', 'dark');

echo $cache->get('theme');

Persistent filesystem caches must be saved:

use Strukt\Cache\Cache;
use Strukt\Cache\Driver\Fs;

$cache = new Cache('settings', Fs::class);
$cache->put('theme', 'dark')->save();

Filesystem Strukt\Cache\Driver\Fs JSON file Uses atomic replacement and defaults to the .cache directory.
Memcached Strukt\Cache\Driver\MemCached Memcached server Requires ext-memcached and an available server.

cache helper behavior

With no dot in the name, cache() returns a Cache facade:

With a dot, the first segment is the namespace and the remainder is the key:

cache('settings.theme', 'dark');
$theme = cache('settings.theme');

The helper defaults to the Memory driver to match the Strukt 2 helper. Pass a
driver class or alias as the third argument when persistence is needed:

cache('settings.theme', 'dark', 'fs');

$theme = cache('settings.theme', null, 'fs');

when a null value must be stored explicitly.

Short names mem, memory, fs, memc, and memcached are bound by
default. A driver name that is not bound and is not a driver class is rejected
with an InvalidArgumentException.

The container also exposes a default cache service so consumers can depend on
the abstraction (dependency inversion):

app(CacheDriverInterface::class); // default driver instance
app('cache');                     // default Cache facade

The default driver is Memory and the default namespace is default; override
them with configuration:

config('cache.default', 'fs');    // short name or driver class
config('cache.namespace', 'app');

Set cache.disable to true to force the Cache facade to use memory storage:

config('cache.disable', true);

$cache = new Cache('temporary', 'fs');
// Uses Memory while cache.disable is enabled.

This setting is intended for tests, local development, and environments where
persistent cache storage should be disabled.

Persistence lifecycle

Memory changes are immediately visible to other instances that use the same
namespace. Filesystem and Memcached changes remain local to the driver until
save() is called.

Recommended lifecycle:

  1. Create a cache namespace.
  2. Read or mutate values with exists(), get(), put(), and remove().
  3. Call save() for filesystem or Memcached storage.
  4. Reopen the namespace to verify persisted values when needed.

Performance and safety

  • Memory storage uses direct arrays and avoids collection wrapper allocation.
  • Dotted path traversal is performed in one pass without repeated string
    wrapper creation.
  • Filesystem writes use a temporary file and atomic replacement.
  • JSON failures are surfaced as exceptions instead of silently creating empty
    caches.
  • Filesystem cache names reject path separators.
  • Memcached setup is lazy and does not make the package unusable when the PHP
    extension is not installed.

Strukt Form

Strukt Form

Rule based form definition, validation, and error reporting, built on the
Strukt rules engine.

A form is described by its rules. There is no docblock parsing, no reflection,
and no request object to hand: you give the form an array of submitted values
and it tells you which fields failed and why. The validation engine lives in
the separate strukt/rules package; this package contributes the form
definition, the submitted values, and the collected failures.

use Strukt\Form\Form;

final class LoginForm extends Form
{
    public function rules(): array
    {
        return [
            'email' => 'required|email',
            'password' => 'required|min_length:8',
        ];
    }
}

$form = new LoginForm();
$form->submit($_POST);

if ($form->validate() === false) {
    foreach ($form->errors() as $field => $messages) {
        // ['email' => ['Email must be a valid email address.']]
    }
}

Install

composer require strukt/form

Defining a form

Extend Form and return the rules, keyed by field name. Each entry is a pipe
separated string, or a list of rule tokens when you prefer to build the list
programmatically.

public function rules(): array
{
    return [
        'name'     => 'required|string|min_length:2|max_length:50',
        'email'    => ['required', 'email', 'max_length:120'],
        'age'      => 'nullable|integer|min:18',
        'role'     => 'required|in:admin,editor,viewer',
        'tags'     => 'array|max_count:5',
        'bio'      => 'nullable|max_length:500',
    ];
}

The full rule list, message overrides, and custom rules are documented in the
strukt/rules package.

Working with a form

Method Purpose
fields() Field names, in declaration order.
rules() The rules definition.
value($field, $default = null) One submitted value.
setValue($field, $value) Set one value.
setValues(array $values) Merge several values.
values() Every submitted value.
isSubmitted() Whether values have been submitted.
submit(array $values = []) Merge values and mark as submitted.

$form->validateWith(['email' => 'ada@example.com', 'password' => 'analytical-engine']);

$form->hasErrors();         // false

$fresh = $form->validated($otherSubmission);  // no errors carried over

Messages

field specific override wins. An override is a complete message, used as
written, and may still use :field, :0, :1, :list, and :format.

{
    return [
        'email.required' => 'We need an email address to reach you.',
        'terms.required' => 'You must accept the terms to continue.',
        'min_length'     => ':field is too short, use at least :0 characters.',
    ];
}

{
    protected function registry(): RuleRegistry
    {
        return RuleRegistry::create()
            ->extend('after', fn (string $field, array $params) => new AfterRule($field, $params[0]));
    }

    public function rules(): array
    {
        return [
            'end'   => 'required|date|after:start',
            'start' => 'required|date',
        ];
    }
}

Strukt Math

Strukt Math

Immutable numeric and matrix primitives. This is the strukt4/math API plus a set of
additive conveniences; every pre-existing behaviour is unchanged, so it is a drop in
replacement.

Install

composer require strukt/math

Number

Strukt\Number wraps a single int or float and returns a new instance from every
operation, so a value can be passed around safely.

use Strukt\Number;

$sum = Number::sum([1, 2, 2.5]);   // 5.5
$mean = Number::sum($column)->parts(count($column));

$average = number(10)->add(0.2)->parts(3);   // 3.4

Aggregating

sum() accepts raw numbers, Number objects, or any iterable, and totals them into a
Number of the same kind: an int only when every input is an int.

Number::sum([1, 2, 3]);          // 6
Number::sum([1, 2.5]);           // 3.5
Number::sum([]);                 // 0
Number::sum($generator);         // any iterable

min() and max() compare the receiver against any number of values and accept
Number arguments. With no arguments they return the receiver, which makes them read
as a clamp when chained off a length.

number(0)->max(1)->yield();      // 1
number(7)->max()->yield();       // 7

Sign, rounding, and roots

number(-4.5)->abs();             // 4.5
number(2.1)->ceil();             // 3  (integer)
number(2.9)->floor();            // 2  (integer)

ceil() and floor() always yield an integer so the result can be used to index a
sequence. round() is unchanged and always yields a float, which is the main
practical difference between the two.

number(8)->log(2);               // 3
number(1000)->log10();           // 3
number(1)->exp();                // 2.718281828459045

log() defaults to the natural logarithm and rejects a base of zero or less.

Dividing

parts() still throws DivisionByZeroError on a zero divisor. partsOr() is the
opt in safe variant and returns a fallback instead:

number(10)->parts(2);            // 5
number(10)->parts(0);            // DivisionByZeroError
number(10)->partsOr(0, 7);       // 7
number(10)->partsOr(0);          // 0

Comparing

equalsWithDelta() is for values that drift in floating point arithmetic, such as
0.1 + 0.2:

number(0.1)->add(0.2)->equals(0.3);                     // false
number(0.1)->add(0.2)->equalsWithDelta(0.3);           // true
number(0.1)->add(0.2)->equalsWithDelta(0.3, 0.0);      // false

The delta is an absolute bound, so it is always taken as a magnitude.

compare() is exposed as an explicit method returning -1, 0, or 1 for use in
sorters, and the existing comparison methods delegate to it rather than each
re-deriving the sign:

number(5)->compare(3);           // 1
number(5)->compare(5.0);         // 0
number(5)->compare(number(3));   // 1

Matrix

Strukt\Matrix is an immutable matrix of Number values. Every operation returns a
new matrix and leaves its operands untouched.

use Strukt\Matrix;

$a = Matrix::create([[1, 2], [3, 4]]);

$a->add(Matrix::create([[1, 1], [1, 1]]))->yield();    // [[2, 3], [4, 5]]
$a->subtract(Matrix::create([[1, 1], [1, 1]]))->yield(); // [[0, 1], [2, 3]]
$a->scale(2)->yield();                                  // [[2, 4], [6, 8]]

add() and subtract() require matching shapes and raise Strukt\Raise otherwise.

Vector products

dot() multiplies matching entries and adds the products. cosineSimilarity()
returns the cosine of the angle between two vectors, which is 1 for parallel vectors,
0 for orthogonal ones, and -1 for opposite ones.

Matrix::dot([1, 2], [3, 4]);                    // 11
Matrix::dot([1, 0], [0, 1]);                    // 0

Matrix::cosineSimilarity([1, 2, 3], [1, 2, 3]); // 1.0
Matrix::cosineSimilarity([1, 0], [0, 1]);       // 0.0

Both pair entries by position, so keys in the input arrays are irrelevant. Mismatched
lengths throw InvalidArgumentException. A zero vector has no direction, so
cosineSimilarity() throws DivisionByZeroError rather than returning NAN.

Norms

The norm is the magnitude of the whole matrix, flattened into a single vector. The
default order is the euclidean norm, the square root of the sum of squares; order 1
is the sum of absolute values.

Matrix::create([[3, 4]])->norm();     // 5
Matrix::create([[1, -2]])->norm(1);   // 3

Any other order throws InvalidArgumentException.

The helper

matrix() returns a proxy, which is handy when the base matrix is only known at
runtime. It also exposes the vector products, which are also available as statics.

$helper = matrix([[1, 2], [3, 4]]);

$helper->dot([1, 2], [3, 4]);     // 11
$helper->norm();                  // sqrt(30)

Transformations

Two classes cover different needs, and both live in this package.

Strukt\Pipeline Strukt\Monad
State mutable, next() returns $this immutable, every call returns a new monad
Evaluation eager, a step runs as it is added strict, a step runs as it is bound
Reuse stateful, reuse re-chains from the last result unlimited, a monad can be shared and re-joined
Best for a short, local chain of steps composing, passing around, branching

Reach for Pipeline when the builder stays local to one run. Reach for Monad when
the value has to be handed around, or when the steps may be grouped differently.

Pipeline

pipeline() feeds steps by position: each step receives the value piped from the
previous step followed by the values it still needs. Only unconsumed values are kept,
so a step that takes no arguments does not grow the pipeline.

use Strukt\Pipeline;

pipeline([12, 3, 2])
    ->next(static fn (int $m, int $x): int => $m * $x)   // 12, 3        => 36
    ->next(static fn (int $mx, int $c): int => $mx + $c) // 36, 2        => 38
    ->next(static fn (int $result): int => $result)      // 38           => 38
    ->yield();                                          // 38

scoped() feeds steps by parameter name. The value piped from the previous step is
bound to the first parameter.

scoped(['c' => 12, 'm' => 3, 'x' => 2])
    ->next(static fn (int $m, int $x): int => $m * $x)
    ->next(static fn (int $mx, int $c): int => $mx + $c)
    ->next(static fn (int $result): int => $result)
    ->yield();                                          // 18

Note that the two forms answer 38 and 18 for the same values. That is deliberate:
the positional form pairs by position, the scoped form by name. Pick one per pipeline
rather than translating between them.

A scoped parameter may not be named after a key that was already in the scope, because
the piped value would overwrite it. That is reported rather than silently applied, so
rename the parameter, or set the value deliberately with with():

scoped(['a' => 1, 'b' => 2])
    ->next(static fn (): int => 10)
    ->next(static fn (int $b): int => $b);      // InvalidArgumentException

with() is the explicit way to replace a scope value, and the key it sets becomes
reserved:

scoped(['a' => 1])->with('a', 100)->next(static fn (int $a): int => $a + 1)->yield();  // 101

A step that throws leaves the pipeline exactly as it was, and a by reference parameter
is rejected because argument unpacking cannot honour one:

$pipeline->next(static function (int &$a) { $a = 99; });   // InvalidArgumentException

hasResult() and isPending() tell a pipeline that has not run yet from one whose step
returned null:

$pipeline = pipeline([1]);

$pipeline->isPending();    // true
$pipeline->hasResult();    // false

monos() is a deprecated shim that guesses the mode from the shape of its input. Use
pipeline() or scoped() instead, because an array such as [1 => 'a', 0 => 'b'] is
treated as a named scope even though its values are a list.

Monad

A monad always holds exactly one value. of lifts a value in, bind composes a step
that may itself return a monad, map is bind composed with of, and join reveals
the value.

use Strukt\Monad;

Monad::of(12)
    ->bind(static fn (int $c): Monad => Monad::of(3)->map(static fn (int $m) => $m * 2))
    ->bind(static fn (int $mx): Monad => Monad::of($mx + 12))
    ->join();   // 18

Nothing mutates, so a monad can be shared and joined as many times as you like:

$base = Monad::of(2);

$base->map(static fn (int $v): int => $v * 2)->join();   // 4
$base->map(static fn (int $v): int => $v * 3)->join();   // 6
$base->join();                                          // 2

bind is strict, so a step error surfaces where it is written rather than later at
join. map does not flatten, so it nests a returned monad; use bind to flatten.

The three monad laws hold for any of, which is what makes grouping irrelevant:

$f = static fn (int $v): Monad => Monad::of($v + 1);
$g = static fn (int $v): Monad => Monad::of($v * 2);
$h = static fn (int $v): Monad => Monad::of($v - 3);

Monad::of(10)->bind($f)->bind($g)->bind($h)->join();                              // 19
Monad::of(10)->bind(static fn (int $v) => $f($v)->bind($g)->bind($h))->join();     // 19

Monad deliberately models sequencing only. It has no notion of failure, so use bind
with a closure that throws, or return an Either from a base package for that.

Backwards compatibility with the previous math package

Range, Counter, helpers.php, and every pre-existing Number and Matrix method
behave exactly as before. The new methods are purely additive, with two deliberate
type choices worth knowing about:

  • ceil() and floor() return an integer rather than a float, which differs from
    round() and is what makes them safe as indexes.
  • sum() preserves the type of its inputs: an int only when every input is an int.

One pre-existing class did change. The old Strukt\Monad was a mutable pipeline with no
bind and no laws, which is what Strukt\Pipeline now is. Migrate as follows:

Old New
new Monad([...]) Pipeline::from([...]) / Pipeline::fromMap([...])
Monad::create([...]) Pipeline::from([...]) / Pipeline::fromMap([...])
->next($step)->yield() unchanged, on Pipeline
monos([...]) pipeline([...]) or scoped([...])
Monad as a value wrapper Monad::of($value)->join()

Because Pipeline now refuses to overwrite a scope key, a step whose first parameter

Design

The rebuild keeps the drop-in Strukt\ namespace and class surface of
strukt1/strukt-key, then removes the rough edges:

  • Bcrypt delegates to native password_hash()/password_verify() with a
    CSPRNG salt, instead of the hand-rolled crypt() salts of the original.
  • Jwt is self-contained (hash_hmac + hash_equals), dropping the
    firebase/php-jwt dependency.
  • Codec generates a fresh random IV per message by default and carries it in
    the output, so one key can be reused safely.
  • The certificate parser returns booleans and DateTime values instead of
    "true"/"false" strings.
  • OpenSSL objects are typed (OpenSSLAsymmetricKey, OpenSSLCertificate,
    OpenSSLCertificateSigningRequest); errors surface as exceptions, not
    silent false.
  • Anonymous chain classes became the named Request and Envelope\Pockets
    value objects.
  • Helpers take explicit arguments; generation defaults are sensible
    (2048-bit RSA, bundled asset/openssl.cnf); tests generate ephemeral keys.

Strukt Process


Typed, resource-safe process execution for PHP 8.2 and later. Strukt Process
supports sequential command batches, line callbacks, captured output,
interactive prompt processes, supervised worker pools, and a supervise
command-line tool for long-running, daemonized supervised processes.

The package is a Strukt 3 rewrite of 'strukt2/process'. It keeps the original
global helpers and process concepts while improving type declarations,
resource cleanup, output draining, error capture, and documentation.

The package depends on 'strukt/base', which supplies the helper registry.

Quick start

Run one command and inspect its output:

<?php

$result = process('printf "hello\n"');

echo $result->outputs();

Stream complete output lines while a command runs:

$result = process(
    'printf "first\nsecond\n"',
    static function (string $line): void {
        echo "received: {$line}";
    },
);

process() waits for each command to finish, drains standard output and
standard error concurrently, and returns a Strukt\ProcessResult.

Running commands

One command

$result = process('php -r "echo 2 + 2;"');

echo $result->outputs(); // 4
$process = $result->resource();

Multiple commands

Commands run in array order. Each command has its own process resource and
captured output:

$result = process([
    'printf "compile\n"',
    'printf "test\n"',
]);

echo $result->outputs(0); // compile
echo $result->outputs(1); // test

$first = $result->resource(0);
$second = $result->resource(1);

An empty command list returns an empty ProcessResult. Every command must be
a non-empty string; invalid commands throw InvalidArgumentException.

Line callbacks

The callback receives complete logical standard-output lines, including their
line endings. A final output fragment without a newline is delivered after
the process closes its output stream.

$lines = [];

process('printf "one\ntwo\n"', static function (string $line) use (&$lines): void {
    $lines[] = trim($line);
});

// ['one', 'two']

Callbacks may also declare no parameters. Standard error is drained to avoid
pipe back-pressure, but it is not sent to the callback.

ProcessResult

Strukt\ProcessResult extends ArrayIterator, so it can be iterated as a list
of Strukt\Process objects.

public function resource(int $idx = 0): Process

Returns the managed process at a zero-based command index. It throws
OutOfBoundsException when the index is absent.

public function outputs(int $idx = 0): ?string

Returns captured logical standard output for a command. It returns null for
an index that has no captured entry and an empty string when the command
produced no output.

errors

public function errors(int $idx = 0): ?string

Returns captured logical standard error for a command. It follows the same

Error output and exit codes

Both output channels are retained:

$result = process('sh -c "printf failure >&2; exit 7"');

echo $result->errors();                 // failure
echo $result->resource()->error();      // failure
echo $result->resource()->close();      // 7, already reaped exit code

Process::run() throws RuntimeException when a command cannot be started.
The process object uses InvalidArgumentException for invalid constructor
handles or empty commands.

Switching channels

The default mapping is standard output to output() and standard error to
error(). The mapping can be switched before starting a process:

switchChannels(true);

$result = process('sh -c "printf output; printf error >&2"');

echo $result->outputs(); // error
echo $result->errors();  // output

switchChannels(false);

The setting affects new Process instances and remains enabled until changed.
It does not change an already-created process.

Interactive processes

Use pprocess() when a command expects input:

$prompt = pprocess('read password; printf "%s\n" "$password"');

$prompt->write('secret');
$prompt->closeInput();

echo $prompt->read(); // secret

write() appends PHP_EOL to the supplied input and returns the number of bytes
written. It throws RuntimeException when standard input is closed or the
write fails. Close standard input when the child must receive EOF.

Interactive processes expose the common process methods as well:

$prompt->read();
$prompt->error();
$prompt->readline();
$prompt->isRunning();
$prompt->terminate();
$prompt->close();

Read output before calling close() if it has not already been captured.
Calling closeInput(), closeOutput(), closeError(), closePipes(), or closeAll()
more than once is safe.

Process pool

ProcessPool supervises a group of concurrently running workers: it spawns a
fixed number of copies of one command, lets you drain their output without
blocking, and tears them all down together. This fits the classic "spawn N
workers, feed a queue, later stop the pool" loop where workers live for the
whole batch rather than for one command.

$pool = new ProcessPool(3);

$pool->start(PHP_BINARY . ' ' . escapeshellarg($workerScript));

while ($pool->running()) {
    $pool->drain(static function (int $index, string $line): void {
        printf("worker %d: %s", $index, $line);
    });
    usleep(100000);
}

$pool->stop();

Start the pool with the pool() helper when you do not need the intermediate
instance:

$pool = pool(3, [PHP_BINARY, $workerScript, '--prefix=demo']);

start

Spawns $size concurrent copies of the command, each with its own standard
three-pipe set so their output stays separate. A string command runs through
the shell; an array command runs the program directly. When the string is a
simple command (no pipes, redirection, quoting, or substitution), the pool
wraps it in exec so the shell replaces itself: the tracked pid is then the
real worker, and terminating the pool kills the worker rather than orphaning
a child of the shell. Standard input is closed up front because supervised
workers rarely read from the parent, and a left-open input pipe risks a
deadlock. Starting twice throws RuntimeException.

drain

Reads whatever each worker produced since the last poll without ever blocking
on a worker. Complete standard-output lines go to the callback as
(int $index, string $line); standard error is drained and retained on each
worker (see Process::error()) but not dispatched. With no callback, drain()
still records the output on the workers for later Process::output().

stop

Terminates every still-running worker and reaps its exit code, returning an
array of codes keyed by spawn index.

Process supervisor

ProcessSupervisor composes a ProcessPool with a restart policy: when a worker
exits (crashes or finishes), supervise() replaces it with a fresh copy of the
original command. The replacement keeps the same slot index, so callers that
track per-slot state keep their numbering across restarts.

$supervisor = new ProcessSupervisor(3, restartCap: 5, backoff: 0.5);

$supervisor->onExit(static function (int $index, int $exitCode): void {
    printf("worker %d exited with %d\n", $index, $exitCode);
});

$supervisor->start(PHP_BINARY . ' ' . escapeshellarg($workerScript));

while (true) {
    $supervisor->supervise(static function (int $index, string $line): void {
        printf("worker %d: %s", $index, $line);
    });
    usleep(100000);
}

Start a supervisor with the supervisor() helper when you do not need the
intermediate instance:

$supervisor = supervisor(3, [PHP_BINARY, $workerScript], restartCap: 5);

Policy

  • restartCap bounds how many times one slot may be restarted; once the cap is
    reached the slot is left dead. A cap of -1 (default) never gives up.
  • backoff throttles restarts of the same slot: after a restart, at least
    $backoff seconds must pass before that slot restarts again, breaking tight
    crash loops.
  • onExit() fires once whenever a worker is found dead -- whether or not it
    will be restarted -- so an owner can reclaim anything the dead worker left in
    flight (re-queue an un-finished job, log the crash, ...).

supervise

supervise() is the only thing a long-running owner needs to call in its loop.
It drains worker output first (complete lines go to the optional callback as
(int $index, string $line)), so the exit hook sees any final lines a worker
wrote before dying, and then revives each dead slot under the policy.

Managed supervisor

ProcessSupervisor supervises from inside the process that owns it. When the
owner is a long-running job -- a queue consumer, a web worker, a scheduled
task -- you usually want it to keep running as a background daemon and to be
observable from other shells. Strukt\ManagedSupervisor adds that layer: it
runs the same supervision loop as a detached daemon and persists everything
worth seeing to a runtime directory.

use Strukt\ManagedSupervisor;

$supervisor = new ManagedSupervisor('mail', size: 3, restartCap: 5);
$supervisor->start(PHP_BINARY . ' ' . escapeshellarg($workerScript));

For every supervisor, the daemon writes three artifacts under the runtime
directory (default ~/.strukt/supervisor, overridable with the
STRUKT_SUPERVISOR_DIR environment variable or the $dir argument):

Artifact Purpose
<name>/supervise.pid Pid of the daemon itself.
<name>/state.json Snapshot of the pool written every supervision pass.
<name>/output.log Combined worker output, one line per slot and supervisor events.

The inspection surface is static on purpose -- status(), ps(), tail(),
kill() and stop() read the pid and state files and never join the daemon:

$state = ManagedSupervisor::status('mail');       // snapshot incl. workers
$running = ManagedSupervisor::running('mail');    // true while the pid is alive
$all = ManagedSupervisor::ps();                   // every pool in the directory
$tail = ManagedSupervisor::tail('mail', 50);      // last 50 log lines
ManagedSupervisor::kill('mail', 0);               // SIGTERM one slot; respawns
ManagedSupervisor::stop('mail');                  // SIGTERM the daemon; reaps

The state snapshot includes the daemon pid, the command, the pool size, the
per-slot worker pids, their running flag, exit code, and restart count, plus
the total restart count and the log path.

Supervisor CLI

The package ships a supervise binary built on the Strukt console. It wraps
ManagedSupervisor with commands to start, list, inspect, kill, and stop
long-running supervised processes:

# daemonize a 2-worker pool that runs worker.php forever
php vendor/bin/supervise start mail "php worker.php" --size=2 --dir=/var/run/sv

# view every supervised pool
php vendor/bin/supervise ps

# show one pool's live state (workers, pids, restarts)
php vendor/bin/supervise status mail

# terminate one worker slot; the daemon restarts it in place
php vendor/bin/supervise kill mail 0

# print the combined worker log
php vendor/bin/supervise logs mail --lines=100

# stop the daemon (reaps workers, removes the pid file)
php vendor/bin/supervise stop mail

Add --json to any command to render the result as JSON for scripting. Run
php vendor/bin/supervise list for the command reference, or generate
markdown documentation with php vendor/bin/supervise docs.

Resource lifecycle

Process::run() closes standard input before waiting so commands receive EOF,
drains both output channels, dispatches pending output, and reaps the child
process. The captured strings remain available through ProcessResult and the
returned Process objects after cleanup.

For manually managed Pprocess instances:

  1. Call write() as needed.
  2. Call closeInput() when no more input will be sent.
  3. Read output and error.
  4. Call close() or closeAll().

All process objects also attempt safe cleanup in __destruct().

Performance characteristics

  • Output and error pipes are drained concurrently with non-blocking reads.
  • The callback is invoked directly, avoiding one event wrapper per line.
  • Command batches are sequential, preserving deterministic ordering.
  • Captured output is appended in chunks rather than rebuilding the complete
    string for every line.
  • Pipe and process cleanup is idempotent, reducing repeated resource checks in
    application code.

Strukt Queue

Strukt Queue

A memcached-backed FIFO message queue with replies for PHP 8.2+, rebuilt from
the scratch-pad strukt1/strukt-queue into a concurrency-safe component. It
supports the classic producer/consumer flow — push a job, pop it, answer with a
reply, wait for the answer — synchronised properly so workers can run in
parallel without losing or duplicating messages.

use Strukt\Queue;

$queue = new Queue(['prefix' => 'acme']);

$id = $queue->push('jobs', ['user' => 7, 'type' => 'export']);

// ...in a worker...
$job = $queue->pop('jobs', $id);
$queue->reply('jobs', $id, 'exported-42.pdf');

// ...in the caller...
$reply = qwait('jobs', $id, 30);

Requirements

  • PHP 8.2+
  • the memcached extension (memcached, libmemcached)
  • a running memcached server (default 127.0.0.1:11211)

Installation

composer require strukt/queue

The package is self-contained; strukt/base (environment values and the helper
registry), strukt/console (the command runtime), and strukt/process (the
worker-pool runner behind the supervised demo) come along automatically.
The kqueue binary is installed into vendor/bin/.

Feature summary

  • FIFO delivery with monotonic, never-reused ids.
  • Exactly-once handoff under parallel workers: pop() is CAS-guarded, so
    no two workers ever receive the same message and the head can never overtake
    the tail.
  • Replies let the caller block until a job is processed and answered.
  • Namespaces (prefix option) isolate many apps or environments on one
    memcached server.
  • Loud failures — the constructor throws instead of die(), a failed
    push() throws instead of silently dropping the message, and wait() gives
    up after a timeout instead of hanging forever.
  • Rescue path — an expired or missing slot is skipped over, never mistaken
    for an empty queue.
  • Crash redelivery — Strukt\Queue\Supervisor keeps a pool of workers
    alive (restart cap + backoff) and returns to the queue any message a dead
    worker claimed but never finished.

Strukt Rules

Strukt Rules

Data driven validation rules, a parser, a registry, and a value validator.

The engine is rule based without being a class per rule. Every built-in rule
has its own declaration in src/Strukt/Rules/Spec/ — arity, parameter format,
failure message, and bail behaviour — and they compile into one specification
table read by the shared Rule class. That table is the single source of
truth: the parser, the message, and the bail behaviour all read from it, so a
rule cannot drift between what it accepts and what it reports.

use Strukt\Rules\Validator;

$errors = (new Validator())->validate(
    ['age' => 12],
    ['age' => 'required|integer|min:18'],
);

// ['age' => ['Age must be at least 18.']]

It powers the form definitions in strukt/form.

The package has no runtime dependencies: it is a standalone engine that only
needs PHP itself.

Install

composer require strukt/rules

Validating values

Validator takes an array of field values and a rules definition keyed by
field name. Each entry is a pipe separated string, or a list of rule tokens.
The same call is available as the standalone check() helper:

use Strukt\Rules\Validator;

$errors = (new Validator())->validate(
    ['age' => 12],
    ['age' => 'required|integer|min:18'],
);

// or the helper:
$errors = check(['age' => 12], ['age' => 'required|integer|min:18']);

Failures are collected per field, in the order the rules were declared.

Rules

Presence

Rule Passes when
required The value is not null, '', or [].
filled Same check as required.
nullable The value is not null.

null, an empty string, and an empty array all count as absent, and 0 and
false do not. A field that is not required and holds an absent value skips
its remaining rules, so an optional field left blank does not also report a type
error.

Types

Rule Passes when
string The value is a string.
integer An int, or a string of digits. 5.5 and 1e3 fail.
numeric is_numeric.
boolean A bool, or 0/1/true/false/on/off/yes/no.
array The value is an array.

Formats

Rule Passes when
email FILTER_VALIDATE_EMAIL.
url FILTER_VALIDATE_URL.
uuid A RFC 4122 UUID.
ip FILTER_VALIDATE_IP.
date A real date in the given format, default Y-m-d.
regex The pattern matches.
alpha Letters only, across scripts.
alpha_num Letters and numbers, across scripts.

date parses the value and formats it again, so 2023-02-30 and
2024-02-30 are rejected rather than silently rolled over:

'born_on' => 'date',           // Y-m-d
'shipped' => 'date:m/d/Y',     // 02/29/2024

regex takes the pattern with or without delimiters, and commas inside a
pattern are kept, so both of these work:

'zip'    => 'regex:^\d{5}$',
'ssn'    => 'regex:/^\d{3}-\d{4}$/',
'csv_id' => 'regex:^\d{3},\d{4}$',

Size

Rule Passes when
min:n The number is at least n.
max:n The number is at most n.
between:min,max The number is within the inclusive range.
length:n The string is exactly n characters.
min_length:n The string is at least n characters.
max_length:n The string is at most n characters.
min_count:n The array has at least n items.
max_count:n The array has at most n items.

Size rules are explicit about what they measure, so a rule never guesses:
min compares numbers, min_length counts characters with mb_strlen rather
than bytes, and min_count counts items.

Sets and fields

Rule Passes when
in:a,b,c The value is one of the listed options.
not_in:a,b,c The value is none of the listed options.
same:field The value equals the named field.
different:field The value differs from the named field.

in and not_in compare loosely, so a 2 submitted as '2' still matches an
option list of strings. same and different read the named field through the
FieldSource every rule receives, which the validator builds from the values.

Bailing

A rule that guards the shape of a value, such as required, integer, or
array, stops the field when it fails. The checks that assume a value is
present do not then add a second, confusing message:

'age' => 'required|integer|min:18'

With age => 'not a number', only Age must be an integer. is reported.

Messages

Every message is built from a readable field label plus the rule's wording.
Underscores and dashes become spaces and only the first letter is capitalized,
so email_address becomes Email address, and min_length:8 on name
becomes Name must be at least 8 characters.

Override a message per rule, or for one field with field.rule. A field
specific override wins. An override is a complete message used as written, and
may still use :field, :0, :1, :list, and :format.

use Strukt\Rules\Validator;
use Strukt\Rules\Messages;

$validator = new Validator(null, new Messages([
    'email.required' => 'We need an email address to reach you.',
    'min_length'     => ':field is too short, use at least :0 characters.',
]));

Custom rules

Implement RuleInterface and register it. A rule receives the value under test
and a FieldSource for reading sibling fields.

use Strukt\Rules\Contract\FieldSource;
use Strukt\Rules\Contract\RuleInterface;

final class AfterRule implements RuleInterface
{
    public function __construct(
        private readonly string $field,
        private readonly string $other,
    ) {
    }

    public function passes(mixed $value, FieldSource $fields): bool
    {
        $other = $fields->value($this->other);

        return is_string($value) && is_string($other) && $value > $other;
    }

    public function message(): string
    {
        return ucfirst($this->field) . ' must be later than ' . $this->other . '.';
    }

    public function bails(): bool
    {
        return false;
    }
}

Register it globally, or pass a registry to the validator.

use Strukt\Rules\RuleRegistry;
use Strukt\Rules\Validator;

RuleRegistry::shared()->extend('after', fn (string $field, array $params) => new AfterRule($field, $params[0]));

$validator = new Validator(RuleRegistry::shared());

extend() accepts a rule instance, which is returned for every field, or a
factory called with the field name and the parsed parameters. Built-in names
cannot be replaced, and a misspelled rule name throws
Strukt\Rules\Exception\UnknownRule while the rules are parsed, listing the
names that are available.

Building another engine

The validator has no concept of a form. strukt/form is one consumer; any
rule based engine can be built on the same foundations. Values reach a rule
through Contract\FieldSource, and a rule set is just an array — nothing in
this package is form specific.

examples/config.php builds a different engine next to form: a config
validator that reaches nested leaves with dot notation, casts string config
values to their declared types before the rules run, and adds its own float
and port rules. It is composition over Validator, and it owns a private
registry and message vocabulary:

use Strukt\Rules\Messages;
use Strukt\Rules\RuleRegistry;
use Strukt\Rules\Validator;

$registry = RuleRegistry::create();
$registry->extend('port', fn (string $field, array $params) => new PortRule($field, $params));

$engine = new Validator($registry, new Messages([
    'required' => ':field is required in the config.',
]));

$errors = $engine->validate($values, $definition);

A private registry keeps an engine's rules and wording local: port and
float exist only on the config engine and never reach
RuleRegistry::shared(), so form validation is unaffected by them.

Strukt Ar

Strukt Ar

A small query builder and active record ORM for SQL databases. It sits directly on
PDO, parameterizes every statement, and keeps the moving parts small enough to read in
one sitting.

A single namespace covers the data-access and active record layers:

Strukt\Ar
Style immediate, explicit writes
Identity one object per call
Writes save()/delete() run at once
Reads query builder per query
Use low-level control

Managed entities — an identity map, a unit of work, and result caching over the very
same models — live in the separate strukt/orm package; see the install note below.

Install

composer require strukt/ar

The package needs at least PHP 8.2 and a PDO driver for your database. For managed
entities — identity map, unit of work, result cache layered over these very same
models and connection — install strukt/orm as well; its README documents how the
two layers interoperate.

Connections

A Strukt\Ar\Connection wraps a PDO instance. Open one through a named constructor and
register it with the manager; the db() helper resolves the default connection from
then on.

use Strukt\Ar\Connection;

Connection::sqlite(':memory:')->asDefault();   // this is what db() returns
Connection::sqlite('app.db')->as('archive');   // named, opt in

db();             // the default connection
db('archive');    // a named connection

mysql() and pgsql() take host, credentials, and similar connection options. pdo()
wraps an existing client. A transaction runs inside transaction(), which commits on
success and rolls back when the callback throws; nested calls share the outer
transaction.

db()->transaction(function (Connection $connection) {
    $connection->execute('UPDATE accounts SET balance = balance - ? WHERE id = ?', [25, 7]);
    $connection->execute('UPDATE accounts SET balance = balance + ? WHERE id = ?', [25, 9]);
});

Connections from environment files

Connection::fromEnv() loads .env file(s) through strukt/base's Env and opens the
connection they describe, registering it as the default. Files are read in order, so a
later file overrides an earlier one — the classic .env plus .env.local pattern.

DB_CONNECTION=sqlite
DB_DATABASE=app.db

Connection::fromEnv('.env', '.env.local');   // defaults to ['.env'];

Keys are read with env(), falling back to the process environment and then to
defaults: DB_CONNECTION (sqlite), DB_DATABASE (database.sqlite),
DB_HOST (127.0.0.1), DB_USERNAME (root), DB_PASSWORD (empty), and
DB_PORT (3306 for mysql, 5432 for pgsql).

The query builder

table() starts a fluent, always parameterized query against one table. Every value is
bound, never interpolated, so clauses are safe by construction.

db()->table('users')
    ->where('active', 1)
    ->where('age', '>', 21)
    ->orderBy('name')
    ->limit(10)
    ->get();

where() accepts equality shorthand, an explicit operator, or a map of equalities;
orWhere(), whereIn(), whereNotIn(), whereNull(), whereNotNull(), and
whereBetween() cover the rest. join() and leftJoin() join without adding
bindings, so a query stays legible.

db()->table('posts')
    ->join('users', 'users.id', 'posts.user_id')
    ->select(['users.name', 'posts.title'])
    ->groupBy('users.name')
    ->get();

Reading gives you rows, single values, or aggregates:

db()->table('users')->where('active', 1)->count(); // 5
db()->table('users')->sum('balance');              // 412.5
db()->table('users')->pluck('name', 'id');         // [1 => 'Sam', ...]
db()->table('users')->where('id', 7)->value('name'); // 'Sam'
db()->table('users')->where('email', $email)->exists(); // true

The last row inside a transaction() insert surfaces through insertGetId(). Writes
are guarded the same way: delete() refuses to run without a where() clause, and
update()/increment()/decrement() touch only the matching rows.

Clauses accumulate on the instance. Keep a base query, then clone it for variations:

$base = db()->table('users')->where('active', 1);
$admins = (clone $base)->where('admin', 1)->get();
$staff  = (clone $base)->where('admin', 0)->get();

toSql() and bindings() expose the compiled statement for debugging.

Active record

Extend Strukt\Ar\Model. One instance is one row: create, read, update, delete, and
their relationships all run through the query builder above, so the two layers compose.

class User extends Model
{
    protected static array $fillable = ['name', 'email', 'is_admin'];

    public function posts(): array
    {
        return $this->hasMany(Post::class);
    }
}

$sam = User::create(['name' => 'Sam', 'email' => 'sam@strukt.test']);
$sam->name;                 // 'Sam', via the columns of the row
$sam->is_admin = true;
$sam->save();

User::find(1);              // reloads the row
User::where('is_admin', 0)->orderBy('name')->get();
User::first();

Table names and keys

The table name is derived from the class short name, pluralized and snake-cased:
PostComment maps to post_comments. Override it, or the key, when the schema differs:

class User extends Model
{
    protected static ?string $table = 'people';
    protected static string $keyName = 'uuid';
}

Fillable, casts, and timestamps

fillable guards every mass assignment through create(), fill(), and update();
a column must be listed before it can be set that way. Individual columns always accept
direct assignment through the property or setAttribute().

casts map how values enter and leave the database. Dates become DateTimeImmutable
on read and return to Y-m-d H:i:s on write; bool, int, float, string, and
array round trip their JSON representation automatically.

Timestamps are maintained when $timestamps is left at its default true:

$sam = User::create([...]);
$sam->created_at;   // '2026-10-02 16:52:58'
$sam->updated_at;   // set again on every save()

The lifecycle

$sam = User::findOrFail(7);      // or types a clear ModelNotFoundException

$sam->update(['name' => 'Samantha']);
$sam->refresh();                 // reloads the row in place
$sam->delete();                  // false when the model does not exist yet

$sam->exists();                  // whether the row is in the database
$sam->key();                     // the primary key value
$sam->toArray();                 // visible, cast columns
$sam->toJson();                  // the same, as JSON

save() inserts when the model is new and updates otherwise, touching only the
columns that changed. fresh reads always go through the query builder, so nothing is
cached at the query layer.

Relationships

Describe a relationship as a method that delegates to hasMany(), hasOne(), or
belongsTo(). Foreign keys are derived from the class names and can be overridden.
Results are computed on the first call and remembered for the life of the instance.

class Post extends Model
{
    public function author(): ?User
    {
        return $this->belongsTo(User::class);
    }

    public function comments(): array
    {
        return $this->hasMany(Comment::class);
    }
}

$post->author()->name;
$user->posts();                    // Post[]
$user->posts()[0]->comments();     // nested, still one query per relation

Magical properties only

Model columns are read through __get/__set. Requesting a column that is neither an
attribute nor a declared relationship throws OutOfBoundsException, so a typo fails
loudly instead of returning null.

Managed entities via strukt/orm

For an identity map, a unit of work, and result caching over these very same models,
install the strukt/orm package:

composer require strukt/orm

It layers managed-entity semantics on top of untouched Strukt\Ar models and the
default connection, so the two layers read and write the same rows through the same
classes:

$sam = orm()->find(User::class, 7);    // one instance per row
$sam->name = 'Samantha';               // nothing written yet
orm()->commit();                       // one transaction

See strukt/orm's README for the full contract, especially how direct Ar writes

php bin/dbcli model:generate --database=app.db --driver=sqlite

php bin/dbcli model:generate --database=app.db --driver=sqlite \

For every table the generator derives the class name (singular, PascalCase), pins
$table, selects a $keyName when the primary key is not id, disables
$timestamps when the table has no created_at/updated_at, and fills $casts from
the column types and $fillable with everything except the key and the timestamp
columns:

// blog_posts -> BlogPost; pk id; no timestamp columns
class BlogPost extends Model
{
    protected static ?string $table = 'blog_posts';
    protected static bool $timestamps = false;
    protected static array $fillable = ['author_id', 'title', 'published_at', 'views'];
    protected static array $casts = [
        'id' => 'int',
        'author_id' => 'int',
        'published_at' => 'datetime',
        'views' => 'int',
    ];
}

vendor/bin/dbcli. Use list to see the available commands.

Creating the database from models

The reverse of model:generate is db:create: it scans a directory for models
that declare a $schema and builds their tables, without needing a hand-written
CREATE TABLE. The primary key and, when $timestamps is on, the
created_at/updated_at columns are generated for you.

class User extends Model
{
    protected static array $schema = [
        'name'    => ['type' => 'string', 'nullable' => false],
        'email'   => ['type' => 'string', 'nullable' => false, 'unique' => true],
        'is_admin' => ['type' => 'bool',  'nullable' => false, 'default' => false],
        'birthday' => ['type' => 'datetime', 'nullable' => true],
    ];
}

php bin/dbcli db:create --database=app.db --driver=sqlite --dir=src

# restrict discovery to one namespace
php bin/dbcli db:create --database=app.db --driver=sqlite \
    --dir=src --namespace=App\Models

php bin/dbcli db:create --driver=mysql --database=app --user=root \
    --password=secret --dir=src/Models

Omit --database to pick the connection from a dotenv file instead (see
--env, which defaults to .env):

php bin/dbcli db:create --dir=src/Models   # from .env

Models without a declared $schema are skipped, and running the command again is
a no-op thanks to IF NOT EXISTS. Described types map to SQLite storage classes:
int/bool to INTEGER, float to REAL, string/text/datetime/json to TEXT, and blob
to BLOB.

Tasker

Strukt Tasker

Strukt Tasker is a small PHP task runner for project-local commands. It loads
tasker.php, registers named PHP callables, executes one task from the shell,
and provides helpers for composing tasks, watching files, and running external
commands.

<center><img src="tasker.jpg" width="200" height="200"></center>

This is the Strukt 3 rewrite of strukt1/strukt-tasker. It keeps the simple
task-file workflow while adding PHP 8.2 types, deterministic registration,
testable application and watcher classes, useful exit codes, complete stream
capture, and safe process cleanup.

Requirements

  • PHP 8.2 or newer
  • proc_open() for the run() helper and command execution
  • ext-zip, inherited from the Strukt Fs dependency
  • strukt/event, strukt/fs, and strukt/process

Installation

composer require strukt/tasker

Composer installs the tasker executable in vendor/bin:

vendor/bin/tasker list

When the command is run in a project without a tasker.php, Tasker creates a
starter file containing a test task.

Quick start

Create a tasker.php file:

<?php

/**
 * Say hello to someone.
 */
task('hello', static function (string $name): void {
    writeln("Hello {$name}!");
});

/**
 * Run a shell command.
 */
task('php-version', static function (): void {
    [$output, $error] = run(PHP_BINARY . ' --version');
    echo $error === '' ? $output : $error;
});

Run the tasks with positional arguments:

vendor/bin/tasker list
vendor/bin/tasker hello Ada
vendor/bin/tasker php-version

Tasker passes command-line values to the task callback as strings. Required and
maximum positional argument counts are checked before invocation.

Built-in commands

The application registers these tasks before loading the project task file:

Command Description
list Lists built-in and project tasks in registration order.
help Shows usage and the task list.
version Prints the Tasker version.

The equivalent switches are --help/-h and --version/-V.

Exit statuses are predictable:

Status Meaning
0 The task completed successfully.
1 The task file or task raised an exception.
64 No task was supplied.
127 The requested task was not registered.

Task-file helpers

Composer loads src/helpers.php automatically. The helpers are registered
conditionally so a host application can provide a function with the same name.

task()

task(string $name, callable $function): Strukt\Task

Registers a task in the active Tasker application. The callback's PHPDoc first
description paragraph is shown by list.

/** Remove generated files. */
task('clean', static function (): void {
    // cleanup
});

Task names are unique. Registering a duplicate throws LogicException instead
of silently replacing an earlier task.

go()

go(string $name, mixed ...$args): mixed

Executes another registered task in the active application and returns its
result. It is useful for composing larger tasks:

task('all', static function (): void {
    go('clean');
    go('build');
});

writeln()

writeln(string|int|float|bool|null $line): void

Writes one scalar value followed by PHP_EOL.

watch()

watch(string $path, callable $callback, int $wait = 1): void

Polls a file or directory until the process is stopped. The callback receives
an array of added, removed, or content-changed paths. The first scan establishes
a baseline and does not call the callback.

task('watch:js', static function (): void {
    watch('app/js', static function (array $files): void {
        foreach ($files as $file) {
            writeln("Changed: {$file}");
        }
    });
});

watch() throws InvalidArgumentException for an unknown path or negative
interval. TaskWatcher provides an iteration limit and injected sleeper for
tests and long-running application integrations.

run()

run(
    string $command,
    ?callable $callback = null,
    ?string $input = null,
): array{0: string, 1: string}

Runs a shell command and returns [output, error]. The optional callback
receives complete standard-output lines, including their line endings. The
optional input is written exactly to standard input and the input pipe is then
closed.

[$output, $error] = run('printf "ready\\n"');

[$output, $error] = run(
    PHP_BINARY . ' -r ' . escapeshellarg('echo stream_get_contents(STDIN);'),
    input: "from task\n",
);

The tuple preserves the Strukt 1 task-file API. Use CommandRunner directly
when the process exit code is important.

The strukt/event dependency is load-bearing: every Strukt\Task wraps a
Strukt\Event (see the Task API below). Its event() and cmd() helpers are
also available in the same task file after Composer loads the package.

Task API

Strukt\Task

Task composes Strukt\Event. It owns the task name, description, and
parameter metadata, while the wrapped event retains the callable as a Closure,
exposes its ReflectionFunction, and applies arguments during execution. This
keeps Task a thin descriptor over the event package instead of reimplementing
callable handling.

new Task(string $name, callable $callback, ?string $description = null)
$task->name(): string
$task->callback(): Closure
$task->reflection(): ReflectionFunction
$task->description(): string
$task->parameters(): list<array>
$task->invoke(array $arguments = []): mixed
$task->invoke(mixed ...$arguments): mixed // through __invoke()

parameters() returns records with name, type, required, and variadic
keys. invoke() supports positional integer-keyed arrays and PHP named
argument arrays. Invalid positional counts throw InvalidArgumentException.

Strukt\TaskRegistry

TaskRegistry is an ordered, isolated collection of tasks:

$registry = new TaskRegistry();
$registry->add(string $name, callable $callback, ?string $description = null): Task
$registry->get(string $name): ?Task
$registry->has(string $name): bool
$registry->names(): list<string>
$registry->all(): list<Task>
$registry->run(string $name, array $arguments = []): mixed
$registry->reset(): void
$registry->count(): int

The registry also implements IteratorAggregate and can be iterated as
Task values keyed by task name. add() rejects duplicate names.

Task-file helpers use the active registry during Tasker::run():

$previous = TaskRegistry::activate($registry);
TaskRegistry::current();       // $registry
TaskRegistry::active();         // $registry or null
TaskRegistry::restore($previous);

Calling task() or go() outside an active application throws
LogicException, which prevents accidental writes to a hidden global queue.

Strukt\Tasker

Tasker is the command-line application object:

new Tasker(
    ?string $directory = null,
    string $taskFile = 'tasker.php',
    ?string $version = null,
    ?callable $outputWriter = null,
    ?callable $errorWriter = null,
)
$tasker->run(array $argv): int
$tasker->registry(): TaskRegistry
$tasker->taskFile(): string
$tasker->taskList(): string
Tasker::defaultTaskFile(): string

directory defaults to the current working directory. A relative task-file
name is resolved below that directory. Output and error writers receive one
string at a time, making the CLI easy to test or embed.

The bin/tasker executable constructs this class with the process argument
vector and exits with the value returned by run().

Strukt\TaskWatcher

TaskWatcher makes polling testable by accepting injectable time and hashing
functions:

new TaskWatcher(
    ?callable $sleeper = null,
    ?callable $fingerprinter = null,
)
$watcher->watch(
    string $path,
    callable $callback,
    int $interval = 1,
    ?int $iterations = null,
): void
$watcher->snapshot(string $path): array<string, string>

The default fingerprinter uses SHA-256. Snapshots are path-sorted and compare
added, removed, and changed files. A null iteration count means the watcher
runs until the process is interrupted.

Command API

Strukt\CommandRunner

$runner = new CommandRunner();
$result = $runner->run(
    string $command,
    ?callable $callback = null,
    ?string $input = null,
): CommandResult

The no-input path delegates to strukt/process, which drains standard output
and standard error concurrently. The input path uses the same three-pipe
protocol and captures both streams before reaping the process. An empty command
throws InvalidArgumentException; a failed process setup throws
RuntimeException.

Strukt\CommandResult

$result->output(): string
$result->error(): string
$result->exitCode(): int
$result->successful(): bool
$result->toArray(): array{0: string, 1: string}

successful() is true only for exit code zero. toArray() provides the output
and error tuple used by the global run() helper.

Performance and safety

  • Task callbacks are converted to closures and reflected once by Strukt\Event
    at registration.
  • Task lookup uses an ordered associative map, so execution does not scan the
    complete task list.
  • External command output and error streams are drained concurrently through
    strukt/process to avoid stderr back-pressure.
  • Watch snapshots are sorted and compared by path, avoiding order-dependent
    false positives.
  • Process pipes are closed and children are reaped on successful and failed
    command paths.
  • Task-file loading is isolated behind Tasker, so tests can use temporary
    project directories and injected writers without changing the process cwd.
